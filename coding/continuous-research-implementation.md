# 持续研究、准确输入与模型发布实施记录

2026-11-13。状态：实施中。本批承接[全量审计与设计](research-template-inputs-and-model-publication-review.md)，实施范围为持续业务报告、方案输入整改、多对象联合研究及结果曲线。对外模型发布目前交付设计报告，独立发布 API 尚未实施；保存私有训练模型不能计为对外发布。旧库只读，249 独立项目为部署目标。

## 已确认的时间与启动语义

平台业务系统经现有业务身份 API 提交启用研究。观察开始/结束是**资料业务日期的闭区间**；每天 Asia/Shanghai 02:00 处理前一天完整资料，因此触发日为开始次日至结束次日。立即运行保留为独立操作。观察期内每个业务日必须有明确批次记录：待资料、计算中、成功或失败，不能缺日不留痕。历史补齐、暂停、恢复不能重复创建同一批次。

暂停阻止新增采集与计算投递；暂停前已经封存并投递的运行允许结束并登记结果。恢复继续原观察期，按日批次唯一键补齐。当前每日人工输入适配要求每个选定对象在该观察日都有记录，不能把旧年或其他对象数据当作当日资料；非逐日人工采样研究需使用单次研究或增加明确的采样日历合同。

真实海豚回调使用 `${system.biz.curdate}`（触发日D）及准确实例ID，后端据固定合同构造D日02:00+08:00，再推导观察日D−1。不能把 `${system.datetime}` 无条件当上海时间。日触发按持久进度排空分页，覆盖超过100个活跃研究。日程在线、时区、Cron及起止覆盖都必须核验。

联合研究首期复用已支持多对象的准确线性回归组件，按明确时间截点保留后续观测评价；多地块静态土壤因素必须具备真实空间变异以满足可辨识性。不新增尚无需求依据的独立算法或宣称完成独立地块泛化评价。

## 实施分段与验证入口

1. 准确数据装配：多地块多快照、不可变数据集；按指标/对象/日期唯一覆盖，拒绝冲突和越权。补方法用途、当前/历史模板映射与原生资料内容说明。正常工作区/业务 HTTP 入口验证，保留旧模型与旧合同行为。
2. 持续报告：受权启用准确方案版本和观察范围；真实海豚 02:00 定时触发创建前日批次。采集与计算仍经现有持久队列和真实海豚执行。任务及批次持久化，输入封存后计算，缺数不伪造、修订不覆盖旧批次。测试正常 API、内部受信触发/回传、时区/起止/幂等/并发/撤权，真实海豚单独联验。
3. 联合研究与私有模型复用：准确土壤、天气和人工目标，跨地块变异与明确划分，三个候选研究分别保存/执行/登记模型/新资料预测；工程目标与科学精度证据分开。另新增[土壤、气象与卫星联合研究](sentinel-research-implementation.md)。对外发布的准确制品、最小预测合同、版本、数据截至和授权规则保留在设计报告；受权他人必须用自己的资料预测，不能借用发布者身份。
4. UI：同一合同投影输入，原生资料逐项列清；任务历史和真实结果曲线，按对象、指标、有效日期及准确版本显示，重叠窗口显式选择批次，不拼接重复点。
5. 迁移/打包/部署：先 metadata 和隔离库 autogenerate，再补 RLS/不可变/唯一性。使用本项目环境回归、Python 文件头检查、组件正反例和真实 249 联验。旧科学合同逐字节保留，新增方法/模板修订追加登记。

## 依赖与职责

- 来源适配器只获取和标准化；数据集装配集中核验覆盖及科学支撑。业务身份/地块授权仍经受信端点，未配置或失联不能转为工作区假身份。
- 持续任务的日期、状态、启停和批次属于持续研究领域；API 只解析身份/协议；存储负责短事务、唯一性与 RLS；海豚负责真实定时和计算调度。不能让 API 自建线程或 sleep 实现每日时钟。
- 模型发布单独管理准确版本与使用授权；既有准确训练制品不改写。科学算法留在独立组件，模型更新不隐式改变已受理预测。
- 结果序列源于保存的准确成果；界面不从固定样例生成持续研究曲线。

## 验收与限制的记录方式

代码/行为测试、提供方取数、真实海豚手动触发、计划正确配置、真正定时触发分别记录。不得把手动触发当作已经观察到凌晨触发。第三方历史产品有延迟时保留待资料状态并按政策补齐；缺正式业务接入和实测目标时明确报告，不伪造农业精度或企业授权。

## 249 实际验收中的调度保护调整（2026-11-13）

专用连接进程维持受信 SSH 并按任务回执恢复，不重复执行未知写入。升级完成后实际研究运行停在已提交：独立海豚日志明确报告 `/scheduler-data` 磁盘使用率约 0.837 超过默认 0.8，Master 和 Worker 均拒绝派发；CPU、内存并非本次原因。该盘仍约 300 GB 可用，任务工作、日志和数据均在本项目该盘挂载。对本项目 `scheduler-compose.yaml` 显式设置 Master/Worker 磁盘保护阈值 0.85，保留开启状态及 CPU/内存阈值；先保存原配置，再仅重建独立海豚。不得清理其他项目文件，不全局关闭保护。验收以原已提交研究真正进入计算并产出结果为准；历史未确认运行不自动重投。后续部署需监测剩余空间，85% 不是扩容替代。

本次实际日批次联验另用独立工作区，由正式 API 保存并发布高温暴露分析，再启用2025-05-29至05-31观察范围。通过已授权海豚 `COMPLEMENT_DATA` 显式补跑05-30、05-31、06-01上海02:00；已实查独立海豚TZ及Token账户均为Asia/Shanghai，补数采用准确列表并逐实例核验。运维辅助脚本只编排API和海豚，不绕过内部触发验真或修改业务库。保存每次提交回执，未知提交停止并对账，不重发；验证每日独立来源与计算、三天结果序列、重复补数无新增批次、启用请求重放及暂停恢复。此证据独立标为手动补数，不计为已经观察到真实02:00自动触发。

网页联验优先沿既有 `scripts/verify_designer_ui.mjs` 使用真实DOM事件和真实HTTP。已尝试普通HTTP及独立受信SSH转发；新连接握手路径仍不稳定，转发未建立，未把该尝试计为DOM联验通过。已保留的专用连接继续负责实际API与运行验收；原生浏览器像素验收仍需可用的浏览器运行环境。

工程参考点预选中的城市中心(126.63E,45.75N)实际被SoilGrids原生像元零值规则拒绝。这是工程参考点缺资料，不修改来源规则、不做邻点后备、不生成假值；保留该失败采集，在验收记录明确撤下未成功的参考点，重新明确选定(125.85E,48.067N)；未开始的另外两点也显式选为(115.67E,41.63N)、(115.1E,37.77N)。这些仅为工程参考位置，不声称是真实已授权地块。任何真实研究对象仍按原准确位置取数，缺测维持拒绝。

真实补数发现保留参数核验把海豚原生`backfillTimeList`日期数组当成参数JSON递归解析，导致合法补数被拒绝。修复只在海豚适配边界分离并核对原生日期列表，`commandParams/startParams`及项目/任务/全局参数的保留名门禁保持。新增经真实`require_daily_instance`入口的正例及嵌套覆盖拒绝回归后再升级。本批API补丁只涉及该核验，计算组件和既有科学合同不变。

诊断曾误带出独立每日回调密钥，立即轮换且清理自产诊断记录。新日驱动采用独立v2工作流，curl从本项目海豚已有私有挂载中的600配置文件读取回调认证头，工作流正文和参数不再含密钥明文。提供方账户仍由既有海豚环境注入，不写入curl配置。原v1日程下线保留历史，v2准确编号/版本进入API配置；先停投递、等已有计算/采集完成，再更新Worker认证与API设置，最后恢复调度。旧失败补数保留，不伪装为成功日批次。

工程来源验收明确保留无合格哨兵景的时间窗：该采集仍记失败/无可用景，快照列表为空；不伪造逐日值。构造工程训练样本时按事先明确的共同对象日期范围选择，记录排除窗口，并由实际样本量、空间变异及回归秩规则决定能否训练。不能把20次采集都宣称成功，也不能把零景当成真实研究已就绪。

每日私有认证文件的权限由`setup_daily.py --prepare-private-trigger`在目标主机统一准备：从已配置准确海豚租户取得实际组号，0640仅授予所有者和该租户主组，实际验证租户可读、无关用户不可读，并保存无秘密的权限证据。正式`setup_daily.py --source-environment-name ...`在任何海豚写入前核对该证据与文件元数据；所有本批发布入口先调用准备入口。规则集中一处，避免未来重发文件时恢复成租户不可读的0600，也不开放全员读取。
