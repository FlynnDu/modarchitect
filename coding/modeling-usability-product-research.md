# 农业数学建模设计器易用性：成熟产品对照研究

2026-11-12 · 研究范围：普通用户定义研究目标、候选因子、候选模型、验证条件，以及组合已有模型的方式。本文先形成产品改造依据，不包含界面实现、代码修改或部署。

## 结论与适用边界

建议以 **JMP Pro 的模型定义和结果解释**作为主要参考，以 **MATLAB Regression Learner 的候选模型训练与比较**作为操作参考，以 **Dataiku Visual ML 的任务配置、预处理封装及模型采用**作为补充。三者提供的参照层次不同，本文没有对产品热度或市场排名作判断。

本项目的普通用户入口适合围绕“研究什么、用哪些因素、采用什么方法、怎样验证、如何使用成果”组织。用户选择“用已有模型的预测作为影响因素”后，系统可以生成底层连接与数据适配；具体采用的对象、日期、时间窗和缺失处理仍要让用户审阅。把这些研究判断一并隐藏，会使用户无法判断组合是否符合研究目的。此段是本项目建议，下面分别列出支撑它的产品事实。

**证据口径：**本次只核对官方文档，没有购买软件或完成三款产品的实机操作。产品文档可以证明已描述的能力与限制，不能证明普通农业用户实际学会了操作。查阅范围为 JMP 19.2、MathWorks 当前标注 R2026b 的帮助页、Dataiku DSS 15 文档；后两者的在线链接会随版本更新，实施前需重新核实。本次不将纯流程编排产品作为数学建模的主参照。

本项目术语以 [GLOSSARY.md](../GLOSSARY.md) 为准；组件表单与执行约束沿用[迁移计划中的组件架构约束](model-designer-migration.md#组件架构约束)。本文中的“多目标”表示多个目标变量，“多因素”表示多个候选因子；二者不能互相代替。

## 用户已经明确的要求

以下来自本次会话，属于需求依据，不是竞品调查结论。

1. 设计器必须支持创建、修改和保存研究方案，并完成训练与后续预测；打开后可以编辑研究，而不只是浏览保存的配置。
2. 候选因子可以持续增加。例如用 NDVI、土壤水分、气温等研究株高，不以一至三个输入作为通用上限。
3. 一份研究可以包含株高、叶面积等多个目标变量。具体方法是否能联合训练，需要另行表达。
4. 曲线和拟合参数由具体方法决定。逻辑斯蒂的参数与曲线不能成为所有模型共有的必填步骤。
5. 一个模型的组件成果可以成为后续模型的输入。连接的对象需要明确到可用预测、参数、特征或训练模型制品。
6. 普通用户需要理解建模关系。配置节点、数据表合并节点和端口代号不能成为完成研究的前置知识。
7. 组件具有统一开发模板、版本化合同、准确输入输出和可复跑正反例。未来用户上传的组件也遵循该合同。
8. 当前独立项目在 249 使用独立数据库和执行环境；本次先提交评估依据，再开展优化。

## 三款产品实际如何组织建模

### JMP Pro：先定义响应与模型效应，再解释预测关系

**已核实事实。** Fit Model 启动窗口把数据列分配到 Y、模型效应、权重等角色；Y 可接收一个或多个响应，但不支持向量值响应列。用户选择拟合方法（Personality），界面随后显示相应选项；效应可包含交互、多项式和嵌套项。模型定义可以保存、再次调出并修改后重跑。部分方法支持 JMP Pro 的 Validation 列，不能概括为每种方法都以同样方式验证。[Fit Model 启动窗口](https://www.jmp.com/support/help/en/19.2/jmp/elements-in-the-fit-model-launch-window.shtml)

Prediction Profiler 在其他因素保持当前取值时展示某一因素变化对应的预测；调整因素会实时更新预测。它适合查看多个响应，也可为各响应设置期望目标与重要程度并优化因素设置。这些曲线表达的是已建立模型的条件预测关系。[Profiler 概览](https://www.jmp.com/support/help/en/19.2/jmp/overview-of-the-prediction-profiler.shtml)、[解释 Profiler](https://www.jmp.com/support/help/en/19.2/jmp/interpret-prediction-profiler.shtml)、[期望目标与优化选项](https://www.jmp.com/support/help/en/19.2/jmp/prediction-profiler-options.shtml)

Model Comparison 是 JMP Pro 的功能，可比较模型预测能力并叠加诊断图；报告按响应列出模型和拟合指标，连续与分类响应采用不同指标。[Model Comparison](https://www.jmp.com/support/help/en/19.2/jmp/model-comparison.shtml)、[比较报告](https://www.jmp.com/support/help/en/19.2/jmp/the-model-comparison-report.shtml)

**可迁移建议。** 将“目标变量”和“候选因子”设为研究的首要对象；方法专属参数跟随候选模型出现。将因素试算、残差和预测范围等解释放在结果区，按方法支持情况显示。JMP 表单仍含较多统计术语，农业普通用户需要中文解释和研究示例；文档不能证明直接照搬其窗口就足够易用。

### MATLAB Regression Learner：把一次比较组织为可保存的学习会话

**已核实事实。** 新会话从表格或矩阵选择一个响应变量，再勾选多个预测因子，并在训练前选择验证方式；回归响应要求为浮点向量。会话可以保存和重开。[建立学习会话](https://www.mathworks.com/help/stats/start-a-classification-learner-app-session.html)

模型预设提供快速训练组、全部方法组及单个方法，并可切换详细说明。用户可以先训练预设，再细化有希望的模型，调节对应方法的参数。[模型预设与方法选项](https://www.mathworks.com/help/stats/choose-regression-model-options.html)

模型列表展示验证成绩，用户选择模型查看图表，复制模型后修改因素或参数，再训练比较；候选之间不需要通过端口相连。应用区分验证结果、独立测试和最终训练模型，最终模型的训练数据仍排除独立测试集。[训练、比较和改进模型](https://www.mathworks.com/help/stats/train-regression-models-in-regression-learner-app.html)

同一会话在训练前确定验证方式，使候选采用同样的验证规则；已导入模型不具备本会话的验证结果，应使用测试数据比较。此处引用的是产品规则，不能把默认五折随机验证直接作为农业研究的通用方案。[验证方式](https://www.mathworks.com/help/stats/choose-a-validation-scheme.html)

**可迁移建议。** 一份研究中用候选模型列表组织“线性回归、非线性生长模型、其他已采用方法”，保留数据与评价条件，复制后改变一个因素组合或一种方法。对用户显示“新建候选、训练选中、比较结果、采用模型、预测新数据”，工程运行身份保留在详情。

### Dataiku Visual ML：在建模任务内部选择因素、预处理与算法

**已核实事实。** Visual ML 在 Lab 中建立任务，在 Design 中配置算法和因素，在 Result 中分析结果，采用后才部署到 Flow。因而平台有流程视图，但建模实验也有独立任务界面。[Lab 与 Visual ML](https://knowledge.dataiku.com/latest/ml/feature-engineering/concept-lab.html)

Design 将目标、训练测试、指标、因素处理、算法与高级选项组织为设置区域。特征处理依据数据类型给出默认配置，也可在该区域使用自定义预处理；算法及超参数在 Modeling 中配置。[Design 页结构](https://knowledge.dataiku.com/latest/ml/model-design/concept-visual-ml-design-tab.html)、[自定义预处理入口](https://knowledge.dataiku.com/latest/ml/custom-models/concept-custom-preprocessing.html)

Prediction 设置支持按时间排序切分、K-fold cross-test 和显式训练测试集合；优化采用的指标可配置。官方默认随机切分不能证明适合本项目的日期连续采样场景。[预测设置](https://doc.dataiku.com/dss/latest/machine-learning/supervised/settings.html)

**可迁移建议。** 通用预处理可以成为候选模型中的“数据处理”设置；普通用户不必逐项添加执行节点。高级参数、代码环境等置于展开区域。这里借鉴的是建模任务的组织方式，农业对象和日期的配对规则仍由本项目定义。

## 多目标能力必须准确表达

| 产品与已核实范围 | 支持事实 | 不能由此推断 |
|---|---|---|
| JMP 19.2 Fit Model 与 Profiler | Fit Model 可选多个响应；Profiler 可探索多个响应及期望目标。 | 每一种拟合方法都支持所有多响应组合；选择多个 Y 就一定联合学习响应间关系。 |
| MATLAB Regression Learner 当前文档入口 | 一个浮点响应向量、多个预测因子。 | MATLAB 其他工具或程序接口不支持多输出；该应用可直接以多个响应列完成同一会话。 |
| Dataiku DSS 15 Multi-target Regression | 至少两个数值目标，共用输入因素；单独设有 Targets 页。 | 多标签分类、数值与类别混合目标、任意方法均支持多目标。 |

Dataiku 多目标回归当前使用 Python 内存后端，支持 scikit-learn 的 Random Forest、Ridge Regression 和 Neural Network；不支持该任务的自定义算法、模型集成及分区模型。结果提供各目标指标及总体指标，后者默认按目标平均。因此“多目标能力存在”与“所有组合功能同时可用”应分别判断。[多目标任务入口](https://doc.dataiku.com/dss/latest/machine-learning/multi-target-regression/introduction.html)、[多目标设置与限制](https://doc.dataiku.com/dss/latest/machine-learning/multi-target-regression/settings.html)、[多目标结果](https://doc.dataiku.com/dss/latest/machine-learning/multi-target-regression/results.html)

**本项目建议。** 研究方案允许声明多个目标变量；方法能力明确区分“单目标”“各目标分别训练”“多个目标联合训练”。选择株高和叶面积时，普通用户仍处于同一研究中。若方法只能分别训练，界面应说明将生成两个模型，并让两者分别展示误差、单位和适用范围。混合类型目标和不兼容方法需给出明确原因与可选处理方式。界面数量不应写死，但实际样本、资源和组件合同仍会构成限制。

总体评分必须保留每目标明细；若把厘米与平方厘米的误差汇总，需明确归一化方式或用户权重，避免一个尺度较大的目标决定全部排序。这里是本项目评价规则建议，并非声称所有竞品都这样实现。

## “组合模型”应提供有明确含义的操作

### 官方已证明的三类相关能力

1. **已有预测公式的复用与公式组合。** JMP 可以保存预测公式用于新行；Profiler 可读取公式列，并将中间公式展开为原始因素。该能力可用于参考“向用户展示最终因素关系、按需展开中间计算”的设计。[保存预测公式](https://www.jmp.com/support/help/en/19.2/jmp/prediction-formula.shtml)、[Profiler 与中间公式](https://www.jmp.com/support/help/en/19.2/jmp/profiler-launch-windows.shtml)
2. **已有模型的测试与采用。** Regression Learner 支持导入符合要求的训练模型，用测试成绩比较并解释行为；不能在应用中复制或重新训练导入模型。导出的模型可预测新数据，输入名称、类型及预处理必须相容。这是模型复用的参考，官方页面没有证明该应用提供任意多阶段串联界面。[导入限制](https://www.mathworks.com/help/stats/import-a-trained-model.html)、[导出与新数据预测](https://www.mathworks.com/help/stats/export-regression-model-to-predict-new-data.html)
3. **多个候选的集成。** Dataiku 可在结果列表选择多个模型并创建 ensemble；要求预处理相同，且时间排序、权重等条件相容。K-Fold cross-test、分区模型等场景有限制；其多目标回归任务另明确不支持集成。这证明“从已选候选发起组合”的交互可行，不能据此认定任意上游制品都能直接接任意下游。[模型集成限制](https://doc.dataiku.com/dss/latest/machine-learning/ensembles.html)

### 本项目建议的用户操作

应按研究含义区分下列操作，避免统一命名为“连起来”。

| 操作 | 农业例子 | 用户需要选择 | 系统处理及审阅内容 |
|---|---|---|---|
| 比较候选模型 | 线性回归与生长模型谁预测株高更好 | 同一目标、评价任务、候选 | 复用评价配对范围，比较每目标误差 |
| 使用已有预测作为因素 | 历史株高模型的预测，加 NDVI 和天气预测株高 | 已有模型、输出、其他因素、下游目标 | 核验模型版本、输出性质、时间可用性和配对范围 |
| 校正已有模型 | 用实测与历史生长预测的偏差训练校正器 | 基础模型、校正目标、因素 | 明确残差方向，生成校正后预测并保留基础预测 |
| 组合多个预测 | 把若干株高预测按规则组合 | 相同含义输出、组合方法 | 核验单位、对象、日期与评价条件 |
| 使用已有模型直接预测 | 使用已经训练好的株高模型预测新地块 | 准确模型制品、新数据、预测日期 | 采用已封存预处理和输出定义，不要求重新训练 |

上表属于拟定能力，不代表当前代码已实现全部操作，也不表示三款产品都提供相同的组合菜单。一般形式可写为：基础预测 `h0(t)` 与 `NDVI(t)、水分(t)、气温(t)` 共同构成下游输入，产生最终 `h(t)`；具体是否合理依赖数据可用时间和验证设计。

**必须保留的研究判断。** 用历史株高训练基础模型，再让其预测进入下游训练时，需要区分独立历史模型、折外预测、按时间回放的预测以及全样本拟合值。若基础模型已经看到用于评价的真实株高，第二阶段再用该输出评价，就失去独立性。建议系统按用户选择的验证任务生成基础预测，并记录每行来源与训练截止日期；未经支持的组合应解释缺少的合同，而不是仅凭线条可以连接就允许运行。

## 面向农业用户的拟定页面结构

以下全部为本项目建议，需要在改造前对照现有入口、契约及调用方形成实现设计。

### 以研究任务开始

建议空白研究从下列顺序展开，允许返回修改。方法选择不固定为逻辑斯蒂。

| 步骤 | 用户看到的问题与示例 | 需要保存的研究含义 |
|---|---|---|
| 研究用途 | “分析株高与哪些因素有关”“预测未来七天株高”“估算当天叶面积”“比较已有模型” | 拟合、同日估算、未来预测、模拟或比较；预测时距 |
| 研究对象与数据 | 作物、地块、种植季、点位；实测表、影像、天气或上传数据 | 对象与观测单位、来源、日期、采样粒度 |
| 目标与因素 | 株高、叶面积；NDVI、土壤水分、气温、已有模型输出 | 多目标、候选因子、单位、可用时间及来源 |
| 候选方法 | 选择已采用方法，或比较一组适用方法 | 准确组件版本、输入输出及方法专属参数 |
| 数据与验证 | “预测同一地块后续日期”“应用到新地块”“应用到新年份” | 数据截止时点、分组/时间划分、评价快照与指标 |
| 检查与运行 | 缺失、配对预览、候选摘要，保存并训练 | 封存版本及输入、实际运行与结果关联 |
| 解释与采用 | 每目标误差、预测范围、因素试算、保存模型并预测新数据 | 准确模型制品、适用范围、后续预测入口 |

“影响因素”是界面可理解的标签；结果中应说明模型反映关联或预测贡献。观测数据训练出的关系不能自动解释为施肥、灌溉等干预的因果效应。

### 让组合成为因素来源选择

在候选因子区提供“添加因素”，来源包括实测变量、派生变量、已有模型输出。选择已有模型后依次显示模型名称与版本、可用输出、输出单位、对应对象和日期。用户完成选择即可看到“已加入：历史生长模型预测株高”。

系统根据组件合同生成实际输入绑定、预处理和表对齐。界面应给出“按点位与观测日期配对”“天气采用前七日累计”“120 行中 113 行配对成功”等可审阅信息；遇到一对多、不同空间尺度、日期容差或插值，给出研究选项和数据预览。自动推断只能作为待确认建议。

配置数据可放在选中候选的属性面板，表适配可收在“数据如何配对”中。用户仍可展开查看组件版本、数据来源和计算关系。专家图需要体现真实依赖，并与表单共同编辑同一份研究方案；任何一个视图修改后都应能在另一个视图准确解释。

### 渐进展示的具体规则

1. 普通视图默认显示目标、因素、方法与评价。权重、正则化、收敛阈值等由方法合同决定是否展示在高级区。
2. 逻辑斯蒂卡片展示其驱动轴、参数范围和曲线相关设置；多因素回归卡片展示因素、项与正则化等实际支持的选项。
3. 候选较多时使用列表、筛选和对照。图中的位置不应决定研究先后顺序。
4. 在结果中区分“训练完成”“通过独立评价”“采用模型”“执行新预测”，分别给出当前可进行的动作。
5. 可提供农业示例帮助起步；从空白研究创建同样必须完成主路径。示例中的变量、因素与连接均应可替换。
6. 后续用户上传组件可补充普通用户所需的名称、用途、目标能力、输入角色及参数说明；字段须与版本化合同一致。此项是待设计的组件目录元数据，不宜由页面按组件名称编写特殊分支。

## 优化顺序与可验证验收

建议首先验证一条从空白开始的普通用户路径，再扩展组合操作；实际调度和制品边界继续沿用项目既有实现。

| 优先事项 | 可观察验收 |
|---|---|
| 目标与因素主导的编辑入口 | 普通用户从空白创建株高研究，加入 NDVI、土壤水分、气温及更多因素；保存重开后可继续修改。全过程不要求编辑 JSON、端口或配置节点。 |
| 方法相关设置 | 从逻辑斯蒂切换到另一种方法时，只展示后者实际支持的参数；无效设置有清楚提示，历史版本仍可解释。 |
| 候选模型与评价 | 同一研究建立两个候选，明确共用的数据与评价范围，分别训练、比较及查看结果。 |
| 多目标 | 一次研究选株高与叶面积，说明是联合还是分别训练；每目标具备独立预测、误差和单位。无法支持的候选给出原因。 |
| 复用已有模型 | 从准确模型制品发起预测，新输入通过同样的变量和预处理检查；不重新训练也可取得预测结果。 |
| 模型输出接后续模型 | 用业务操作添加已有预测为因素；可看配对结果和来源。无效单位、对象粒度、缺失配对及训练泄漏样例均能被拒绝或要求修正。 |
| 表单与图一致 | 两视图切换不丢目标、因素、参数、组件版本和连接；历史方案可打开并解释。 |
| 普通用户理解 | 用未参与开发的农业用户完成指定任务，记录成功率、需解释的位置和错误选择。产品文档与开发者演示不代替此项验证。 |

**待验证项：**现有方案合同承载上述用户语义的完整程度；两个已有方案的真实页面入口与编辑问题；当前变量目录是否具备单位、空间粒度与时间可用性信息；多阶段训练的评价合同；普通用户在没有开发者说明时能否独立完成任务。本文没有检查或更改这些代码行为，主代理应分别登记事实与缺口。

**资料冲突处理：**Dataiku 的一般 Design 知识页仍概述三个单目标预测类型，而 DSS 15 专门的 Multi-target Regression 文档已明确新增任务与限制。本文以专门任务文档证明其多目标能力，并记录版本，不从概览页缺少条目推断产品不存在该能力。
