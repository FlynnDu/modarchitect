## 实现边界

- 外层三个阶段与配置内层导航共同呈现一份 `ResearchPlan`，导航本身不产生额外的科学配置或保存修订。
- 选择模板从当前准确目录及执行能力读取。首个普通验收采用已接通的地块种植季标准指标和多变量线性回归；随机森林、样方/点位及未接通来源明确标记限制，不能选中后伪造可运行结果。
- 基础信息、用途表、因素目标和日期均修改原方案。可用的源字段来自系统目录；不让用户在新表单中重定义科学单位。
- 来源与观测在独立步骤展示；来源定义、通道可用和观测存在分别表达。合成示例始终标注工程验收性质。
- 检查与确认使用现有服务端 `/designer/validate` 完整编译结果。运行按钮只在最终确认处触发既有保存与执行，错误返回对应配置步骤；最终服务端仍是运行资格的权威。
- 保存模型和新数据预测仍用既有资源，非训练分析不显示模型登记；不把“保存为候选模型”显示成科研发布生效。
- 历史 JSON、草稿、旧串联编辑和高级组件图继续可打开，不用易用表单覆盖未知结构。

## 模块与调用方

`index.html` 负责页面语义和布局；`wizard.css` 负责原型样式；`wizard.js` 负责导航、字段和确认视图；方案编辑仍调用 `editor.js` / `modeling.js`。`studio.js` 只装配共享状态并通知视图，`research.js` 仍负责保存/运行/模型 HTTP 交互。来源选择继续使用 `system-inputs.js`，确认摘要读取同一份方案及运行状态。

新模块按实际职责控制数量，不为每个步骤建立独立服务。没有必要新增运行 API 或数据库表。若实施时发现权威校验缺口，先补本文、再在既有领域入口实现并增加行为验收。
