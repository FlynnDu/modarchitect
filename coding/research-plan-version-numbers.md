# 研究方案版本号

本文记录上一轮未发布的本地实现。版本名称与版本身份的发布边界以[研究方案应用与版本身份](research-plan-version-identity.md)的审查结论为准。

基础信息提供可选的方案版本号，自定义与采用模板共用规则。采用模板时继续展示来源及其准确版本。模板引用、配置摘要、并发修订及执行用的冻结版本沿用原合同。

版本号采用 `主版本.次版本.修订` 三段数字，参考 [语义化版本的数字格式](https://semver.org/lang/zh-CN/)。默认从 `1.0.0` 开始，配置或者该修订附带的观测发生变化时，在已用最大版本号上递增第三段。研究方法或输入输出合同有实质变化时由研究人员选择主、次版本，例如更换研究方法设为 `2.0.0`，兼容增加可选指标可设为 `1.1.0`。每段最多九位，禁止前导零，首版和后续保存均可手动指定。当第三段耗尽时要求明确指定新的主或次版本。相同内容且未改变版本的重复保存沿用原修订及编号。

- 唯一约束以同一个 `design_id` 内的全部已分配版本号为范围。不同研究方案可以各自从 `1.0.0` 开始。指定曾被本方案使用的号码返回 409，格式错误返回 422，两者均可定位到 `version`。仅更改号码也推进修订，旧号继续占用。
- 企业接口 11/12 的保存请求接受外层可选 `version`。个人工作区与旧草稿写入口共用同一保存规则。查询列表和详情返回 `version`，原保存回执保持三个字段，前端通过 14 回读已分配号码。前端提交手填值，留空交给服务端分配。
- 草稿行锁保护修订比较与分配，独立的不可变登记表以 `(design_id, revision)` 和 `(design_id, version)` 约束历史，附保存配置摘要。配置、版本号、观测和回执在各自既有的同一保存事务中提交。共同格式和自动递增算法放在方案合同，版本号唯一性由存储层执行，API 保留授权及错误协议。
- 0012 为每个历史草稿的现有修订登记 `1.0.0`，从启用版本管理时开始形成可查的编号记录。历史配置、修订、回执和冻结执行合同保持原样。

验收覆盖新建自动编号、模板派生保留来源、手动指定和重开、自动递增、相同内容重试、占用号及错误格式定位、同一修订并发修改、企业隔离、旧草稿迁移和线上接口形态兼容。数据库测试使用独立 PostgreSQL 环境。
