# 研究平台的输入、计算、输出与执行规则

2026-11-12。用户明确要求以平台规则为核心，输入调整包括新增、删除与替换，UI 随规则跟进。

## 一个权威判断链

平台先区分“能保存的研究草稿”“结构与科学合同成立的方案”“此时此地可执行的研究”“可复用的模型”和“经过独立验证的科研结论”。任一层成立都不自动授予下一层资格。

方案检查沿用 `ResearchPlan`、`compile_plan`、系统来源校验、组件执行声明和已登记运行制品；把当前启动中的准备逻辑提取到共用准备模块。只读检查和实际启动调用同一准备函数。检查不写草稿、不发布版本、不创建运行、不占用调度；启动还需核验修订、授权并封存输入。

## 必须执行的规则

| 规则 | 权威依据与行为 |
| --- | --- |
| 变量定义 | 系统目录规定含义、准确版本、单位、观察尺度、来源和取数属性；用户选择已有定义，不任意重命名来源或改单位 |
| 输入编辑 | 分开声明记录新增/删除/替换、输入来源新增/删除、因素增删、目标增删和分析指标选择；`conditional` 必须重新检查，不能当作无条件允许 |
| 指定资料 | 原生输入只能来自已批准的准确模板及匹配摘要；只允许登记参数变化；日期或指标选择不构成底层资料替换资格 |
| 普通观测 | 完整对象与业务日期唯一、列完整、数值有限且在定义范围内；数据非空。不同种植季、地块和单位不能自动混配 |
| 数据资格 | 区分系统定义、通道接通和本次数据就绪；历史私有变量与合成演示不授予真实输入资格；估计和模拟不能充当实测标签 |
| 组件输入 | 必需端口有连接，配置满足准确组件 Schema，因素和目标必须出现在实际接入表中；数量由组件合同约束，平台不统一限制为几个因素 |
| 组件串联 | 使用准确类型、版本、形态、单位与时空对齐；只允许无环依赖。派生变量保留原性质和上游来源，不增加为外部实测输入 |
| 组件输出 | 公开输出必须引用实际节点端口；模型状态、数据表与分析摘要各守合同。声明输出不等于运行已经产生输出 |
| 研究操作 | 训练、预测、分析、模拟和标定按每个节点声明核验；组件版本获准且准确运行制品可用才允许提交 |
| 模型复用 | 训练须产出可复用状态；预测引用原训练状态与预处理，不重新训练。分析报告或留出预测结果不能自动登记为预测模型 |
| 评价 | 同对象/日期/指标/单位的合格实测才用于评价；保留覆盖与误差，不把完成计算等同验证通过，不把模拟或估计结果当真值 |
| 状态与权限 | 方案版本、研究运行、执行尝试和真实调度身份分别保存；所有私有读写按当前主体授权；重复请求沿用准确输入，过期尝试不能发布成果 |

规则适用范围随当前合同版本明确。逐地块部分启动、持续模拟入库、后到观测重评、科研发布与报告复核尚未完成，不用字符串状态或空接口冒充已经具备。

## API

- 公开规则目录返回版本、规则标识、说明和实现范围。
- 方案目录/详情的 `input_policy` 只保留 `mode`、`editable`，参数白名单复用既有 `editable_parameters`。记录调整包含新增、删除和替换；输入、因素、目标调整包含增删。声明允许调整仍需重新校验，固定定义和来源由全平台规则约束，不重复返回布尔字段。旧 `execution_mode` 保留。
- `POST /api/v1/workspace/check-execution` 请求只有 `definition`、`operation` 和需要时的 `observations`、`data_kind`；指定方案身份从已有定义读取，不重复提交。响应只含 `can_execute` 与 `issues`；问题只含 `rule`、`path`、`message`。预检成功不跳过实际启动检查。
- 实际启动违反准备规则时保持原 `detail` 字符串，并附 `issues`，旧调用继续读 `detail`，新页面按规则标识判断。
- 卡片流程读取同一政策和实际运行结果；新增/删除后清除旧的就绪展示。当前编辑状态和历史运行版本分别显示。

不为 UI 额外返回卡片标题、颜色、建议、固定五步连线或重复计数。准确运行方案读取与检查结果各为一个最小资源，复用现有方案和结果接口。

## 可验收结果

通过正常 HTTP 入口验证：新增目录因素、删除非必需因素、删除必需输入、删除全部目标、增加缺列因素、修改科学单位、用估计值作标签、错误串联、循环、指定资料替换、超出白名单改参、合法指标子集、指标全空及无可复用状态。合法变更可以运行；无效变更可定位且不入队。保留历史模板、旧训练请求、已保存模型与预测回归。预检与真正启动必须得出相同拒绝规则。
