## 结构和兼容

- `system_inputs` 负责目录定义与来源合同的验证。新自定义方案使用 1.5。遵照该版本的设计与保存路径，外部输入须已有准确绑定，指标定义及科学范围只读。计划来源和待接入端口可保留准确登记。组件生成的派生列仍由组件合同声明。已保存的历史版本及旧版批准示例按原合同解释。
- `validation` 继续编译模型、绑定与变量用途。业务 API 10 和 11/12 的设计错误共用既有定位。本期不新增对外 API 或持久化字段。
- 技术编辑器由 `panels.js` 展示变量详情。`wizard.js` 检查当前定义及负责确认页交互。`research.js` 复用现有工作区存储，提供只保存方案的入口。
- 当前研究工作区的单次运行、取数及历史报告入口继续按各自合同使用。页面的进度与上线状态以平台的实际记录为准。

## 验收

1. 基本信息四项可见。两页采用同一标准指标时，已采用状态和互斥原因清晰。技术视图只读，不出现自定义指标或采样时间设置入口。
2. 1.5 配置提交改写的指标属性、未绑定的外部输入或训练输入与目标重叠，后端明确定位错误。目录计划来源可以参与设计，已有历史示例能照常打开。
3. 模板和自定义方案经检查后保存。保存方案不要求创建数据采集或调度任务，按 ID 回读后还原相同配置及流程。新增与修改的回执、重复请求和企业隔离行为用隔离库验证。
4. 飞书原图文清单保留原文、截图，追加本期核对结果和实际预览截图。
