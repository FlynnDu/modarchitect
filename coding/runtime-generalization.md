# 研究运行通用化与用途合同兼容改造

2026-11-12。依据 [原型与 API 评估](figma-ui-api-assessment.md) 开始实施。保留单一权威组件图、准确版本、封存输入、隔离文件协议、现有数据库与 DolphinScheduler。

## 本批边界与验收

本批完成基础框架可独立验收的两个纵向切片：

1. **运行按任务及组件合同判断产物。** 训练、推理、分析、模拟和标定分别有显式操作身份；已登记组件才可用于对应操作。旧训练及预测协议继续有效；非训练分析不用伪造训练模型。新增一个可独立复跑的标准观测描述统计组件，通过保存、发布、真实调度、成果重开验证非训练闭环。未登记的模拟/标定算法继续明确拒绝，不用演示组件冒充已接通能力。
2. **新方案按节点请求绑定解释变量用途。** 1.5 方案从组件 Schema 与真实请求生成节点级用途视图，允许同一标准变量在不同候选节点分别作因素和标签。参数仍只有权威图中的一份，不新增平行因素列表；旧 1.0—1.4 保留全局角色行为与准确载荷。

样方/点位科学对象接入、真实外部来源、独立评价与模型生效、团队共享仍按评估中的后续批次推进。它们依赖正式业务合同与数据，不随本批通用化被标成已实现。图端口、变量本体、单位和来源资格不放宽。

## 接口与模块职责

- `contracts/research/execution.py`：操作、组件执行能力及输入用途视图的纯类型；不访问数据库、Docker或调度。
- `execution_contracts.py`：读取准确组件的声明；旧已冻结组件通过带合同摘要的兼容清单解释。集中核验操作、训练状态端口与推理组件，生成用途视图。新增同协议组件只需声明和登记，不向执行器增加算法名分支。
- `runtime/contracts.py`：保留旧 `TrainingRequest`，新增显式操作请求；`POST /workspace/runs` 接受两种格式。旧请求身份摘要不因新默认字段改变。运行响应明确列出任务类型及状态。
- `runtime/service.py`：复用一条保存/发布/封存/投递流程；运行前检查全部节点可用于该操作、输入来源可用、训练标签为实测。推理继续引用准确模型及冻结制品。
- `runtime/executor.py`：按封存合同执行图，训练才要求可复用状态。非训练产物作为普通成果返回，不进入训练模型注册。预测保留原模型及训练来源，不重新拟合。
- `runtime/store.py` 与迁移：只扩展运行类型约束，原唯一键、事务、队列和 RLS 不变。不重建研究库，模型登记仍限成功训练。
- 新描述统计组件：沿既有组件模板/文件协议交付清单、实现、合成正例、独立预期和应拒绝样例。仅计算所选列计数、范围、均值及样本标准差，保留单位/性质/来源，不生成作物预测结论。
- 页面：增加明确的非训练分析样例，按实际运行类型显示操作/成果；继续使用同一草稿和图。既有训练、串联和模型预测入口不改变。

## 合同和兼容策略

新执行能力包含支持的操作、可选训练状态输出、可选准确推理组件及字段用途阶段。历史组件原 JSON 不改写；兼容清单使用准确组件版本及原合同摘要，错误摘要、未知版本、制品登记与声明不一致均拒绝。新组件在自身版本化声明中提供能力。

新 1.5 方案允许探索任务没有评价目标；有预测/训练/评价目标时仍逐项检查用途和实测性质。1.0—1.4 的导入、导出、科学摘要不改变。输入来源始终采用系统目录；模拟/预测结果不能变成实测标签。

运行类型扩展需要增量迁移。先在项目专用 PostgreSQL 应用自动生成并审阅结构差异，再加入准确新组件登记。旧版本回退只能解释既有运行类型，新类型不用于旧进程；部署先停止投递、等活动任务完成，更新 API/Worker/调度后再恢复投递。

## 已授权的验证入口

沿用项目已有验收边界：公开 HTTP 合同/个人工作区、组件独立文件协议、Worker 领取回传、专用 PostgreSQL 与本项目隔离海豚。用户已要求组件可验证并授权兼容改造；测试通过这些既有入口，不引入额外需要确认的内部接口。

按纵向切片先用一个失败的非训练 HTTP/执行行为用例证明当前限制，再实现最小通路。回归包括旧多变量/串联、旧排队载荷、模型推理状态、来源拒绝、跨工作区隔离、错误操作/缺产物拒绝；新用途视图与旧全局角色分别验证。完成后跑本次所有 Python 文件头检查、静态检查、相应 JS 测试、独立组件正反例、包内源码核对及 249 实际调度。

### 复核与仍未完成的范围

已按工程规范核对职责和调用方：操作类型是纯合同，准确能力解释集中在单一模块，领域服务检查用途/来源，Worker 检查封存声明，描述统计独立制品不增加执行器算法分支。旧清单通过原摘要的兼容文件解释；部署制品仍由服务端决定。无可解析 Git HEAD，因此以旧 wheel 的准确合同及冻结库记录为兼容基线，没有虚报 Git 差异评审结果。

当前工具没有可用的网页浏览器控制面，未完成原生浏览器布局和视觉验收；已经完成 DOM 交互、线上资产及真实 API 验证。完整五步原型尚未实现：点位/单株/样方数据适配、真实外部来源、随机森林等新增方法、独立评价快照、模型版本生效、团队权限、节点实时事件及完整响应合同继续按主评估逐批落实。模拟/标定只有操作合同，本批没有登记对应算法，明确拒绝不支持的任务。

本地最初试迁移后发现新组件缺少原生参数声明，冻结触发器正确阻止了修改；未绕过不可变约束。修正候选制品后改用全新专用 `runtime_generic_v2` 验收库重新迁移和测试，249 只接收最终合同。
