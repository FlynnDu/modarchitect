# 从农业研究问题到可读模型关系：易用性评估与改造报告

2026-11-12。研究对象为当前 `/designer/`，依据用户红框截图、实际页面入口、版本化方案、科学组件和真实运行记录。报告先于本次界面实现建立。竞品事实和一手来源的完整核查见 [产品研究](modeling-usability-product-research.md)。

## 结论

当前页面首先要求用户理解执行器需要的表、配置、端口和合并操作，研究目标反而退到背景。问题不仅是名词难懂：全部计算节点被放在一列，配置与观测使用同样的边，向下计算却从左右端口绕行，节点位置不能表达数学依赖。用户必须先掌握软件实现才能表达自己的研究问题。

默认入口改为“预测什么 → 已知什么 → 怎样建立关系 → 怎样检验 → 保存并使用模型”。模型关系是主视图，组件图作为可展开的精确实现。两视图读取、修改同一份方案，保存、发布及运行继续走已有合同与调度，不能维护两份含义不同的配置。

## 用户已明确的问题与要求

1. 不会使用设计器的人不知道“合并”是什么，也不知道何时要选这些组件。
2. 配置独立成节点造成视觉负担，用户容易把一次技术配置误当成一个数学模型。
3. 连线杂乱，方向与顺序不清，应符合人对数学公式和推导顺序的理解。
4. 支持任意多个候选因素和多个目标；不能把所有方法都套成曲线拟合及固定拟合参数。
5. 上一个模型的输出应能用于下一个模型，但用户首先应理解“为什么需要这个中间结果”。
6. 底层组件应可验证、版本化、独立复跑；易用界面不能牺牲可追溯性和严谨性。
7. 本次先形成报告，再优化当前项目，保留真实保存、训练、模型复用与预测闭环。

## 从数学建模看“合并”

### 多个因素通常只需要一个模型

设同一研究对象、同一日期的已知因素为 `X=(天数, NDVI, 土壤水分, 气温)`，目标为 `Y=(株高, 叶面积)`。研究是寻找 `Ŷ=f(X;θ)`，由观测训练参数 `θ`，再用新 `X` 计算预测值。因素多不意味着要多放几个模型。当前线性组件对各目标分别拟合线性方程，共用选定因素，不是联合估计目标之间的误差相关性。

### 串联应源于一个明确的中间量

例如先用较早的实测株高拟合生长规律，得到按日期计算的趋势估计 `b(t)`，再研究：

```text
历史实测株高与天数 → 生长趋势模型 → b(t)
b(t)、当日 NDVI、土壤水分、气温 → 最终预测模型 → 预测株高
```

线性基线可写作 `预测株高=β₀+βb·b(t)+βN·NDVI+βW·土壤水分+βT·气温`。第二个模型同时接收中间指标和已有观测。它并非在任何农业研究中都优于直接模型，应在相同独立评价范围比较后判断。

### 配对不是又一个数学模型

历史模型产生一张带对象和日期的趋势估计表，NDVI、气温等在观测表中。计算前要把同一地块、作物、种植季、日期的数据放到同一条记录中。“合并预测因子”实际上完成这一步对齐，并保留单位、来源和预测性质；不是求和、平均，也不是再拟合一遍。

普通用户的操作应是“把历史株高估计作为一个已知因素”，系统据明确合同处理配对。界面仍需说明按什么对象和日期、是否允许时间窗、缺失怎样处理。当前组件按完整对象与业务日期精确配对，缺失或单位错误会拒绝；不能在界面声称会自动插值或就近配对。

### 防止看上去合理、科学上不成立

- 上游预测不能冒充下游的实测训练目标。上下游同目标时，中间预测应作为因素，最终标签仍取独立实测。
- 不能把未来实测或用未来目标拟合出的曲线输回过去。当前演示分为较早的曲线拟合期、后续回归训练期、再后续留出评价期。
- 如果未来引入同批样本上的堆叠模型，需要明确样本外预测或交叉拟合。scikit-learn 的 [StackingRegressor 文档](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.StackingRegressor.html)说明二层训练所用的交叉验证预测及同数据预训练模型的过拟合风险；该原则不能用随机时间切分替代农业时序验证。
- 多天观测不是多个独立地块重复。单地块合成演示的极小误差不代表跨地块、品种、季节的预测能力。
- 用户输入预测日期的气温、NDVI后，是利用已知因素估测该日期目标；没有未来因素来源时，不应显示为已经具备未来多日预报能力。

这里选择有相关成熟建模能力的产品，不将知名度当作市场份额排名，也不把通用流程工具当作主竞品。

| MATLAB Regression Learner | 导入数据后选择响应、因素、验证方式，训练和比较候选模型。[官方入口](https://www.mathworks.com/help/stats/regression-learner-app.html) | 按任务组织操作，明确训练、验证、预测，提供清晰起步路径 | 其官方入口的响应为单响应向量；本项目应保留自身多目标合同，不能照抄成单目标 |

本项目主参考采用 JMP 的“目标/因素/模型关系”，操作路径参考 Regression Learner，后台可追溯编排借鉴成熟数据科学平台。需要吸收的是交互组织方法，而非照着某个产品堆同名节点。

## 交互与节点规划

### 面向研究者的默认视图

第一屏直接给出两种有解释的研究方式：

- **直接建立预测关系。** 已有要预测的实测指标及其候选因素，先建立一个可检验的基线模型。因素很多也可从这里开始。
- **先计算中间指标，再预测。** 某个因素本身来自另一个模型，例如历史生长趋势，再与环境因素共同预测最终目标。只有研究需要这个中间量时才选。

样例入口标注合成数据。已载入方案后，按当前实际参数显示目标、多选因素、方法和训练截止日；支持修改，不能只展示固定讲解图。新用户能够从这两个入口生成已连接的方案，后续仍能打开完整组件图。

模型关系区按推导顺序显示每步：**需要什么 → 做什么 → 得到什么**。每个模型使用有意义的变量名、单位及关系式。历史结果明确叫“趋势估计”，避免让人误以为它是实测。配置不作为独立研究节点，放进相应模型的设置。已知的精确配对只作为相邻步骤之间的解释；不能将未知或有科学意义的变换一律隐藏。

验证区展示实际日期切分、当前观测条数及对象数，区分历史拟合、最终训练、留出评价。结果区用变量名称、单位和每目标误差解释训练成果，后续预测表单说明应输入哪些已知因素。

### 完整组件图

使用真实拓扑层级从左到右排布：观测 → 上游模型 → 数据对齐 → 下游模型 → 成果。分支处对齐，跨层边走独立通道，边用箭头明确方向；窄屏允许横向查看，不能把端口与文字挤在一起。

参数默认内收，不再把三份配置画成与实测表同等的数据源，也不画参数穿越多层的长线。模型提供“设置”入口，仍可修改原方案的准确配置。提供“自动整理”恢复依赖顺序。保留原方案保存的手动位置，只有主动整理才清除位置，不能在查看时静默改写研究配置。

模型关系视图为同一方案的语义投影，完整图显示实际变换和版本。遇到不支持的自定义结构，应完整显示其步骤并引导使用组件图，不得用一张固定的示例关系图掩盖实际计算。

## 本批实现边界与目录

本批采用现有原生 JavaScript、CSS 和 FastAPI 静态资产，保持既有企业授权、方案合同、科学代码、数据库和调度协议。新增建模说明与设置模块，复用已有草稿编辑、保存和运行入口。图布局独立为纯函数，展示层只负责渲染和事件。

| 模块 | 职责 |
|---|---|
| `modeling.js` | 从真实方案推导研究关系、设置入口、日期分组及已知模板编辑，未知结构显式返回支持范围 |
| `modeling-view.js` | 渲染默认研究页与研究者用语，将编辑事件交给同一方案所有者 |
| `graph-layout.js` | 从真实边计算拓扑层级、稳定顺序和可复用的正交路径 |
| `visuals.js` | 将布局与端口位置绘到已有画布，保留选择、设置和移动操作 |
| `studio.js`、`research.js` | 共享当前方案、数据、运行及模型状态，连接既有 API |

### 界面设计规格

用途为农业研究者理解、编辑及验证预测关系。视觉沿用当前项目的自然色研究工作台，主信息从研究目标向模型推导展开。色彩复用 `#176047`、`#162d23`、`#566b60`、`#e7f2eb`、`#faf0df`；字体沿用 Geist、Noto Sans SC、Microsoft YaHei，保留已有字体回退，不引入远程字体。以宽模型关系区与较窄设置说明区组织内容，适配小屏单列。复用当前 token、按钮和表单样式，不引入新组件框架、图标依赖或装饰性图片。

## 验收方式

1. 从空白页能说明何时用直接模型、何时用中间指标，无须先找合并组件。
2. 两份方案显示与实际配置一致的目标、因素、关系式、输入来源和日期区间；修改因素、目标或日期会修改同一份可保存的方案。
3. 配置节点默认消失，数据对齐在默认视图有业务解释；完整图仍可看到实际对齐步骤。
4. 完整图的每个数据依赖都朝后续层，自动整理与手动位置行为可验证，跨层线不穿过节点。
5. 用纯逻辑测试覆盖乱序节点、分支、循环、未知结构、串联来源和设置变更；通过真实合同检查编辑后的方案。
6. 在 249 更新应用资产，复跑保存、重开、训练、模型保存及推理；沿用已有准确科学制品和调度。页面验证与接口验证分别记录。

## 首批落地结果

已在当前设计器实现两个研究起步入口、与真实方案同步的研究名称/问题/目标/因素/截止日设置、按实际参数生成的关系式、历史拟合/最终训练/留出评价的观测数量，以及中间指标的来源与精确日期配对解释。线性关系式使用“截距、因素、权重”解释，各目标分别学习；只有这一已知方法显示线性权重，不把它作为所有模型的通用参数。

完整组件图使用真实 DAG 分层，从观测到成果逐层向右；参数归入对应模型设置。跨层连接走节点下方的独立正交通道，每条线带方向箭头。小屏保留横向阅读，端口仍在左右两侧。打开视图保留原手动位置，主动点击“按依赖自动整理”才清除位置。公式、设置和组件图共用同一份可保存研究定义。

引导编辑只覆盖已验收的普通数值预测结构。分组/处理变量、自定义评价门槛、运行时参数绑定、未知组件、错误的上游来源等情况均回到完整步骤及组件设置，避免误改其他科研语义。任意已训练子模型的选择器、候选比较、残差校正、通用元数据驱动的引导表单、配对后实际损失行数展示，按后续批次推进；当前已有的是两阶段训练模板及其整条模型的复用预测。

### 验证边界

研究关系及交互经过 DOM 测试，部署端经过真实接口和调度验证。原生浏览器工具仍因无法可靠识别 Windows 当前网址而中止，本批没有绕过该限制；屏幕像素、触屏手势和真实浏览器交互未记录为已验收。jsdom 不提供布局引擎，其测试不能证明最终像素级连线效果。本报告依据用户截图与源码定位原问题，改造后的几何规则由纯函数测试和实际 DOM 层级检查验证。
