# 研究方案设计与保存的API闭环

2026-11-16。用户确认本批终点为：前端通过业务后端转接API浏览方案/自定义设计，完整选择目录指标和基础模型，先校验再保存；保存成功后业务系统自行落库，本系统可查询配置并用于流程图。业务库不做实际验证，取数和计算实现是否接通不作为本批设计验收门槛。

## 已发现断点

1. 指标目录的部分来源绑定为空，configure直接拒绝；页面额外按field_season限制选择，把取数/适配实现状态误用为设计资格。
2. 模型选择同时校验运行操作/训练状态和自动接线，未来尚未实现的资料适配不能形成可保存的设计。
3. design-saves只验证草稿文件、输入绑定和采样核权，未强制完整结构检查；单独check通过不是保存时的并发可信证据。
4. 对接文档没有完整说明自定义起点、校验错误定位、已保存方案列表/详情和流程图的复原步骤；业务库成功回写边界需明确。

## 约定与最小改造

- 目录设计资格与执行资格分开。所有已登记准确指标允许配置；未接通的来源使用版本化的计划来源绑定，固定定义、单位和采样尺度，明确待接入；不冒充实测数据或已经接通的通道。实际运行仍拒绝未接通来源。
- 组件按准确版本和端口构图。设计可使用尚未登记制品或操作适配的版本；缺少实现的外部数据以typed deferred输入表示，并保留需要的变量，不能以任意观测表伪装序列、网格或模型。科学单位、目标真值性质及图的连线一致性仍校验。
- 选择时可立即配置，或明确选择“先保留为待配置步骤”，将参数端口也保留为deferred。已填写的configuration参数继续校验，不静默吞掉错误。
- 复用compile_plan，显式区分设计检查与运行适配检查。设计检查只验证图、参数、变量和准确目录，不要求本次数据、制品或实际取数。运行保持原有完整规则；设计成功不代表可以启动。
- design-saves写入前再次调用同一设计检查，失败HTTP422返回issues，path及可用的node/port定位错误；不落方案、不生成回执。已有暂存草稿接口保留不完整编辑语义，不作为正式提交入口。
- API只保存本系统数据库并返回design_id/revision/configuration_sha256。业务系统先持久化请求ID和正文，收到回执后自行保存业务关联；请求重放、回执查询和修订冲突规则保持。两库不声称分布式原子提交。
- 流程图复用已保存详情的composition、input_recipes、variables及组件目录，节点/连线以准确引用生成，不另存第二份图或新增重复图形字段。

## 对接文档按接口拆分

本轮仅整理文档，不修改接口合同、数据库或运行版本。两份对接文档按闭环实际使用的每个接口分别提供标题、用途、方法/路径、请求字段、curl和响应示例；前端文档同时说明响应字段对应的界面内容、编辑状态与后续请求。区分公共方案库、企业已保存方案、基础计算组件和已训练模型，不混用ID或版本。

示例从当前接口和已验收配置采集，长配置提供完整JSON文件及明确标记的字段节选。只读接口及配置生成/检查接口重新请求核对；保存接口复用既有隔离验收请求的准确幂等重放，不创建额外运行。业务库字段和失败恢复约定保留，Key仍由部署环境提供。

实际完成：两份文档各18个接口示例（新增与修改共用design-saves，合计17种HTTP操作），每项有用途、参数/请求体、curl、响应和字段解释。前端另列来源展示、参数Schema、端口与分支、错误定位和保存后重查规则；完整JSON集中在docs/examples/model-designer.json。

验证：21次真实curl返回符合预期，包含准确保存请求重放、查回执、重查方案、目录/模型合同、生成/检查/导入及缺连线反例。两份文档的全部路径/方法与线上OpenAPI一致；58段JSON可解析，40段shell通过bash语法检查，链接目标存在。训练模型详情的正例按代码合同说明并明确标注，隔离设计企业无训练模型，未创建任务补数据。无产品源码、数据库或运行版本改动。
