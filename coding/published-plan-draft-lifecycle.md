# 正式方案与独立编辑草稿生命周期

2026-11-19。发布后的正式配置不可修改，应用研究只能引用正式版本。再次编辑必须明确开启新的草稿，不能影响已经发布的版本、地块研究、数据集和模型引用。

## 当前缺口与目标

`research_design_versions` 已有不可变触发器和准确版本外键；`ResearchStudies.create` 按正式 UUID 创建实例。当前 `design-saves`、暂存更新和工作区更新仍能在发布后继续改同一个工作草稿，没有显式重新编辑动作。

保留长期 `design_id` 和现有按方案查询的路由。新增独立草稿记录 `research_design_draft_sessions`，每次编辑有自己的 `draft_id`、来源正式版本、开启修订和初始摘要；发布时记录对应正式版本并关闭。`research_design_drafts` 作为当前编辑配置工作位引用该草稿，历史正式正文仍仅由版本表持有，不复制为第二份正式业务事实。

## 状态和接口

初建草稿 → 编辑保存 → 发布并关闭；基于某个正式版本开启全新草稿 → 编辑 → 发布新版本。正式版本和原有研究引用始终不变。

- 新增 `POST /api/v1/research/design-versions/{version_id}/drafts`，沿用服务 Key、企业范围和 `Idempotency-Key`。返回独立草稿及开启修订的不可变回执，随后按方案详情读取配置。并发或重复请求不覆盖现有活动草稿；同一键重放不重新开启旧草稿。
- 详情增加 `draft_id`、`draft_state`、`base_version_id`、`published_version_id`。保存仍沿用既有三字段回执，草稿修订跨编辑轮次单调递增，旧请求不能误写新草稿。
- 发布后的保存返回 409，要求显式开启新草稿。重复发布关闭草稿返回同一个正式版本；新草稿发布产生新正式 UUID，即使没有改变配置，也不会把旧版本当作新发布结果。
- 工作区增加同义入口和“基于已发布版本编辑”操作；正式配置只读展示，编辑必须先成功开启新草稿。执行、采集和报告不隐式重定向到新版本。

## 数据库与历史兼容

0016 为历史当前草稿登记独立身份。使用准确方案合同规范化后比较正式版本；完全一致的当前草稿登记为已发布，存在未发布修改的保留活动草稿，不能依据原始 JSON 缺省字段或表中是否有行猜测状态。既有正式 UUID、正文、摘要、版本名称、研究及模型外键保持不变。

新表沿用强制 RLS、同方案复合外键及唯一幂等键；数据库禁止重写已关闭草稿，新的编辑轮次只能引用同方案正式版本。先锁方案、再锁当前草稿，发布和开启编辑共用锁序，外部授权请求不持有数据库锁。老直接发布合同仍只追加准确正式版本，不更新旧版本；正常业务编辑采用上述显式流程。

## 验收

先复现发布后仍能保存和缺少新草稿入口，再通过 HTTP 与隔离 PostgreSQL 验证关闭草稿拒绝写、开启新身份、同键重放、并发冲突、跨企业拒绝和无内容变化的新发布。既有版本在新草稿保存与发布前后逐字节和摘要一致，已有地块研究与模型仍引用原 UUID。迁移前后核对正式版本全量身份，现有前端调用方与接口文档同步更新；完成包级回归、Ruff 和全部本次 Python 文件头检查。
