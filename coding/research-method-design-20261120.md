# 计算与评价的统一配置与展示

2026-11-20，本地开发。面向客户演示和普通研究用户，研究方案明确生长目标、候选因素、学习关系、验证与可复用预测。第 5 步只提供一个配置入口，其余是方案预览。用户确定研究资料与目标后，平台生成可确定的配置，剩余确需决策的字段才请用户选择。

配置在第 5 步结束，下一步进入「检查与确认」，统一核对预期成果、评价适用范围并保存。旧「结果与版本」链接转到确认页。

## 边界和接口

沿用组件的做法，先冻结准确版本的合同，再给出采用资格，最后由运行服务核对已登记的制品。计算方式目录只登记组件引用、界面名称、关系说明和运行时字段绑定。变量角色、参数、模型状态、预测组件以及成果端口直接读取组件声明。新增方法须先交付可独立训练、预测和验证的组件，然后登记准确版本。页面继续用同一套表单和预览。

| 概念 | 合同与责任 |
| --- | --- |
| 计算方式 | 可以拟合关系、产生模型状态、提供独立推理和验证预测表的公开选项。底层组件还包括转换、统计和历史执行依赖。 |
| 方法目录 | `GET /api/v1/model-center/research-methods` 返回 `schema_version/items`。每项提供准确组件身份、关系说明、参数 Schema、平台默认值、运行时字段、成果和部署运行状态。前端用同一张卡片和同一套表单解释合同。 |
| 方案预览 | 复用 `inspection`。第一条流程显示“观测资料 → 学习与验证 → 研究成果”。第二条显示“新资料 + 保存的模型 → 计算 → 各目标预测值”，其中外部因素由预测执行使用的同一规则推导。输入和输出以指标列呈现，不填入假设数值。方向提示适配窄屏，支持系统的减少动态效果设置。 |
| 方案保存 | 保存研究目标、候选因素、方法、评价规则。训练截止日期由 `runtime_fields` 表达为运行时规则，保存时无需真实数据或具体日期。保留既有准确版本中的固定日期。 |
| 一次训练 | 预检和启动共同按封存观测的不同业务日排序，前约 80% 日期用于训练，剩余日期留出。同一天所有地块同组，至少各有一个日期。实际方法仍核验最低样本、变异和范围。运行保存实际截止日，训练方法不能把验证样本用于拟合。 |

平台以已选的目标与因素、可用端口和科学单位生成初始配置。线性、随机森林、XGBoost、高斯过程复用因素与目标列。逻辑斯蒂使用已登记的观测日期转换；仅拟合一个、能配对实测的目标。多个目标时让用户明确选择一个，不能悄悄截取第一项。固定随机种子来自组件 Schema。缺少目标、因素或连接不伪造值；让用户回原资料步骤补齐，或在方法弹窗确认选择。历史多阶段拟合各自已有的边界继续解释，因为单一日期切分不足以为两阶段拟合生成不同边界。

```mermaid
flowchart LR
    A[研究资料和生长目标] --> B[卡片选择计算方式]
    B --> C[沿用已选指标与平台规则]
    C --> D[服务端校验并预览]
    D --> E[保存方案]
    E --> F[实际训练时封存数据并切分日期]
    F --> G[模型 预测 留出评价]
```

## 全目录审查标准

可新选方法同时具备可采用的准确版本、关系训练、模型状态、独立预测、留出预测表、自有观测输入与可统一解释的表单。描述统计只有样本数量、范围、均值、变异，不能输出因素关系或预测。天气规则、固定样例分析、蒸散量核算、推理和转换组件留作相应历史依赖或高级组装使用。逻辑斯蒂采用已有可训练、可复用的曲线合同，其关系为观测时间与生长目标，不能解释不同外部因素的影响。新版方法目录展示部署能力，实际启动仍以数据和部署检查为准。

首次盘点覆盖原选择器的 28 项。能改造的优先复用已存在的准确训练与预测版本，撤下普通场景的冗余入口。

## 统一响应

新目录返回 `schema_version: "1.0"` 和 `items`。每个条目使用下面的字段。

| 字段 | 用途 |
| --- | --- |
| `component` | `{code, revision}`，准确训练组件身份。 |
| `name`、`relationship` | 卡片名称与可学习的关系。 |
| `execution` | `available` 表示训练和预测制品已登记，`design_only` 表示目前只可设计。两者均须在启动时检查本次资料。 |
| `configuration.parameter_schema` | 从组件取得的 JSON Schema，包含参数类型、必填字段、可选观测列，以及表单说明。 |
| `configuration.input_uses` | 从组件执行合同取得每个观测字段的角色和阶段，前端可沿用已选因素、目标和驱动。 |
| `configuration.defaults` | 从 Schema 的默认值或常量投影。 |
| `configuration.runtime_fields` | 组件参数名到运行槽位的映射。例如线性回归 `{"training_end":"training_holdout_cutoff_date"}`；将映射放入对应配置配方的 `runtime_fields`，从 `value` 省略同名字段。 |
| `outputs` | 准确声明的训练结果和预测表端口。 |

设计校验共用组件 Schema 和业务规则。预检与启动使用同一份日期切分逻辑，执行器绑定已封存日期。模型记录保留训练所用的实际边界。历史跨阶段拟合保留既有日期；普通组件选择没有手填日期。

- `node --test --test-concurrency=1 tests/test_*.mjs` 通过 127 项。覆盖目录卡片、无日期表单、只读预览、预测所需资料及历史草稿。

- Chrome 在 1440 像素和 390 像素宽度核对两条流程、方法切换、页面横向溢出及减少动态效果设置。工作区通过真实接口完成配置保存和新页面重开。

## 第 5 步的通用计算配置

第 2 步保留研究资料及候选因素编辑，第 3 步保留目标编辑与实测参照。重复的参数和成果展示从这两步移除。第 4 步核对数据来源，实际采集平台资料的入口移至「研究数据与运行」。第 5 步按设计稿保留当前方法与更换入口，中部并列展示数据资源和计算配置，窄屏单列排列。数据资源将输入变量和预测目标分别显示为带数量、标签和详情的卡片，并显示真实观测的日期范围与样本数。训练策略一行展示数据划分方式、训练集比例和验证集比例。评价指标分别显示选中状态。两条流程图退出第 5 步。

`inspection.evaluation` 提供实际可用的策略、比例和指标选中状态。日期自动留出支持编辑训练比例（整数 1–99），验证比例由平台计算。按日期将同一天的记录保留在同一组，既有的指定窗口及历史方案保留原有规则。评价指标可编辑，至少选一项，已用于数值门槛的指标保持选中。指标从执行器已有的决定系数、均方根误差、平均绝对误差和平均偏差中选；机理模拟和分析只显示其适用设置。高级参数来自准确组件 Schema。

两个编辑入口均通过正常草稿更新将选择写入 `definition.evaluation.training_percent` 和 `definition.evaluation.metrics`。旧方案缺省时仍使用 80% 与原有指标集合，序列化省略未配置的字段，保留历史摘要。发布沿用既有的版本封存流程，运行时使用封存设置计算留出边界与评价指标。验收覆盖调整后保存、重新打开、发布、运行及历史默认配置。见[计算组件开发规则](../docs/calculation-component-rules.md)。

训练方案的简易方法选择入口指向声明可复用模型输出的计算组件。只有多个符合条件的节点时才要求选择步骤。卫星 NDVI 计算与土壤气象配对、日期派生等上游数据准备按原方案执行。技术工作区保留完整管线。

第 5 步「当前训练模型」的标题采用和方法选择相同的节点规则。上游资料处理按模型的实际绑定追溯，并在第 5 步和选择弹窗中显示为只读说明。完整链条仍可在检查与确认中核对。

## 发布版本验收

FastAPI 的 OpenAPI 版本从已安装的 modarchitect 制品元数据读取，Swagger 使用同一份 OpenAPI。发布以 `pyproject.toml` 的版本为源，构建指定 Git 标签对应的安装包。测试从应用的 HTTP 入口核对生成的 `info.version`。部署后经对外代理核对该字段和文档页面，并与正式标签及安装版本比对。
