# 农业科研输入与组件建议复核

本文件保留改造前的建议评审。来源框架、必要科学支撑和第三方取数已按首批范围落地；当前状态及后续能力边界见249 验收。

2026-11-12。依据用户本次粘贴的《从农业科研与数学建模角度审查这份数据结构》、现有源码及一手标准核对。附件作为审查材料，其中建议不是新的执行指令。本文更新设计约定，未修改运行代码、数据库、目录制品或 249 部署。

## 判断

**核心建议合理，应与来源解耦一起优化：数据取得后，还要能证明其科学含义和研究用途相容。** 优化集中于来源快照、时空支撑、观测证据、节点用途和评价规则，不按附件的示意 JSON 原样新增所有字段或实体。

当前目录是资源发现投影，不承担完整实验、观测、模型和评价体系的全部职责。仅检查 63 项目录，无法据此断定项目没有研究角色、采集协议或试验单元合同；另一方面，存在这些合同也不等于已进入实际运行闭环。下面分别记录。

## 必须修正的字段归属

附件后半段把 `value_nature`、`spatial_support`、`temporal_behavior` 建议放进全局科学变量表，与其前文强调“来源与记录不同”存在张力。本项目采用如下归属：

| 归属 | 保存的事实 |
| --- | --- |
| 科学指标 | 量的定义、规范单位、性状/对象约束、有效范围、分类及可核实的外部标准映射 |
| 准确来源与方法 | 产品性质、原始字段、允许时空支撑/取数属性、测量或转换方法、质量规则 |
| 观测记录/来源快照 | 实际观察对象、位置或覆盖区、深度、有效时间、修订、值性质、原始证据、校准/质量及取得时间 |
| 组件输入输出声明 | 因素、标签、驱动、状态或参数等节点用途、阶段及输出性质；仅声明该组件实际支持的能力 |
| 研究及评价快照 | 预测起点和目标提前量、实际样本划分、独立单元、数据采用与剔除、预处理拟合范围及评价依据 |

科学指标可以对允许支撑与测量对象作约束，但不能把某次像元坐标、实测/预测性质或设备永久固定在指标上。单株高度、冠层高度、地块统计高度的定义可能不同，不能只凭同名“株高”认定可互换。品种与环境属于研究/生物材料背景，不是每行都复制一份；生育期和管理事件按实际日期与对象关联，也不要求每个模型都提供全部物候阶段。

数值算法需要的预测目标与机理模型的系统状态是两个维度。例如 LAI 可以是被预测的状态，实测 LAI 又可在另一节点作标签或校准约束。模型参数通常来自配置/标定状态，不因叫“变量”就要求放入采集目录；Logistic 的 K/r/t0 也不成为所有模型的公共必填项。

## 科学兼容与处理规则

### 时空和统计支撑

保留 `unit_kind` 的观察单元类型，并补充实际支撑：点位/样株/覆盖区身份、参考几何或像元与分辨率、深度区间及单位、有效时间范围与日界，以及对指定轴执行的统计操作。土层仍引用准确 `depth` selector，其结构化上下界由合同解析得到，不接受另一份客户端可独立修改的深度。

日均、日极值和日累计不能互换；应记录统计轴、区间、方法及完整性。NDVI 的空间标准差不是时间标准差，也不是测量误差。范围、频率和更新时刻不完整时，不能假设自动适配成功。

空间聚合、时间窗口、重采样、单位转换、缺失处理都是明确的方法。提供方标准化只承担来源合同允许的转换；研究专属的聚合/插补/特征选择属于准确处理组件或输入装配配方，须保留制品与参数，不藏在下载器中。同一门禁仍由一个权威模块实现。

### 防止泄漏与虚假独立样本

以 `H(t+7)=f(H(t), NDVI(t), T[历史窗口], …)` 为例，研究先声明预测起点 t、7 天提前量及准确目标日期。每个输入都必须满足在 t 时可获得的条件。t+7 才观测的 NDVI 不能作为 t 时已知输入；如采用在 t 前发布、覆盖未来日期的气象预报，必须有单独获准的预报来源、发布时间与性质，不能沿用当前历史天气绑定。

现有回归按 training_end 切分训练行与随后日期行，预测仍需要目标日期行中的因素。若这些因素是后来才得到的实测 NDVI 或气象，它验证的是给定同期因素的关系预测，不能仅凭日期晚于训练集就称为“提前 7 天预报”。本次建议补的任务起点/提前量及可用时间门禁正是为解决这一差别；当前代码尚未实现完整检查。

数据准备分成三种不同责任：来源原文按固定方法规范化；按研究目标建立样本及候选记录关系；对已划分的训练范围拟合可学习处理。训练、开发验证和最终测试的准确记录与单元划分先封存，归一化、插补、变量选择、目标变换等只能在对应训练范围内拟合，应用阶段复用该状态。

串联方案中，上游拟合状态和下游派生输入都要检查其训练范围；使用留出标签拟合的基线预测不得进入下游训练/测试。需要交叉拟合时由准确方法明确声明，不自动推测。存在完整预测流程不等于已具备全部这些通用检查。

沿用 `experimental_unit_ref` 区分试验重复和重复观测。同株多日、同小区多株及同像元静态土壤多日展开都不能按行数冒充独立重复。训练/验证按研究目的选择时间、地块、种植季或试验单元；只有方法支持并通过实际执行验收后，才对外声明某种划分可用。

**新增问题：静态因子的可辨识性。** 单地块单季的土壤参考可能全程恒定；它在带截距回归中可能与截距共线。现有回归已检查训练矩阵秩并拒绝不可辨识因素。来源接通不能取消这个科学门禁，也不能偷偷删因子。需要跨对象差异、不同问题设定或显式参数用途时，由研究人员采用相应方案。

### 质量、不确定性与数据产品

原始值与质量标记保留；研究采用、过滤或剔除由明确规则形成记录清单和原因。缺测不是 0，异常标记不意味着允许原地修改原始证据。测量值、估计值、预测值的来源性质不因转换成统一单位而改变。

测量误差、空间离散度、参数不确定性和预测区间分别表达；有数值时须有定义、单位、方法及适用范围。没有可靠误差估计时保留未知，不能从 NDVI 区域标准差推导株高预测置信度。EnKF 等方法需要的误差协方差及状态—观测映射由对应组件合同要求，不能成为所有模型必填内容。

平台分析保留“影像/报告产品 → 准确处理活动 → 指标记录”的关联，区分外部已处理产品与本研究上游成果。既有平台产品可作为合格外部输入被采用，本研究计算产生的量仍为派生输出，不能借目录登记重标成实测。

## 组件和 API 的最小边界

保持[来源架构](input-source-architecture.md)的获取端口、准确适配器与依赖注入，科学增强放在对应合同及处理方法中，不把全部科学判断加到厂商客户端。

新增元数据按实际使用放在定义、上下文、快照或评价资源；API 引用准确资源，不把样本树、设备配置、影像掩膜和全部统计字段复制到每次 request/response。新字段必须指出生产方、消费方、权威校验和缺省语义，没有消费者的建议字段暂不增加。

**本次发现的历史兼容边界：** `components/multivariate_regression/component.py::split_rows` 对输入表要求恰好 `columns/rows/source_sha256`，`runtime/executor.py::observation_input` 当前保留表外层字段。若直接往组件输入表增加来源快照、质量或支撑字段，旧准确制品会拒绝。新元数据应留在受权资源及运行来源清单，装配时按准确端口合同投影计算输入；确需消费丰富元数据的组件发布新版本。旧 JSON 序列化和幂等摘要保持原样，不能仅因“字段可选”就假设兼容。

标准元数据只借鉴所需语义，不宣称当前 JSON 已符合整个 MIAPPE、CF 或 SensorThings API，也不为复用概念强制更换对外 HTTP 风格。

## 实施优先级与验收

1. **来源接入的必要基础。** 准确历史解析/当前采用、获取与快照、实际单位/时空/深度/质量门禁、记录引用与旧端口投影。天气/土壤沿原定任务继续，未满足科学门禁的来源仍阻断。
2. **真实研究的输入装配。** 把既有 StudyContext/试验单元和实际快照接入准备路径，核对目标日期/提前量、可用时间、独立单元和固定划分；先完成受支持的地块日值研究，不伪装支持单株或所有跨年验证。
3. **各类来源与模型扩展。** 补人工协议与测量证据、平台产品谱系、设备部署和校准，按真实需要增加科学分类、管理事件、生物材料、质量及误差合同。更复杂模型/同化能力另行按组件模板交付。

验收必须包含：同指标多节点不同用途、点位与地块错配、错土层/日界、静态重复不增独立单元、未来信息拒绝、预处理及上游模型的训练范围、错来源修订/摘要、跨主体引用、旧组件精确输入、换源后旧方案和旧模型解释。真实提供方、隔离数据库和 DolphinScheduler 分别取证；本轮仅审查与设计，未宣称这些新能力通过运行验收。

本轮实际复核：使用项目 `.venv`，在测试子进程清除数据库环境变量后执行 `python -m pytest tests/test_execution_contracts.py tests/test_system_inputs.py -q --tb=short`，**19 passed**，有一条既存 TestClient 弃用警告。另用真实 `ObservationTable.sealed()` 和 `train_predict` 验证：原表产出模型与预测；添加来源快照字段后被准确旧组件以 `Invalid observation table` 拒绝。仅文档变更，未新增/修改 Python 文件，因此不涉及本轮文件头检查，也未开展新数据库/真实调度或农业精度验收。

## 一手依据与适用范围

- [MIAPPE 官方项目](https://github.com/MIAPPE/MIAPPE)及[数据清单](https://raw.githubusercontent.com/MIAPPE/MIAPPE/master/MIAPPE_Checklist_Data_Model.tsv)：支持实验、生物材料、观测单元和 trait/method/scale 的元数据关联。本项目借鉴这些语义，不照搬实体或把所有字段强制必填。
- [CF 1.13，Cell Methods](https://cfconventions.org/Data/cf-conventions/cf-conventions-1.13/cf-conventions.html#cell-methods)：支持明确统计轴、方法和范围；此规范面向科学数据约定，不直接规定本平台 API/数据库结构。
- [OGC SensorThings API 1.1](https://docs.ogc.org/is/18-088/18-088.html)：区分设备、传感器、数据流、观测对象、现象时间、结果时间与质量。作为设备接入语义参照，不要求研究 API 实现完整 SensorThings 服务。
- [FAO AquaCrop 输入要求](https://www.fao.org/aquacrop/overview/input-requirements/)：气象、作物、土壤与管理共同构成该模型的输入背景；不同模型仍按自己的准确合同要求输入。
- [How to build a crop model. A review](https://link.springer.com/article/10.1007/s13593-022-00854-9)：研究目的、数据质量和渐进增加复杂度的依据。全文明确聚焦过程模型，其结论不直接当作所有机器学习组件的执行规范。
- [scikit-learn 官方防泄漏说明](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage)：预处理和特征选择必须遵守训练范围，推理复用已拟合状态。引用的是一般训练边界，不引入该库作为本轮新依赖。
