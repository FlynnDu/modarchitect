# 研究设计器输入输出与完成性专项盘点

## 范围与验收

覆盖全部当前公开研究方案、已登记基础模型及自定义入口；核对02研究资料、03目标与成果、模型替换、完整检查和正式保存。保留既有变量与组件版本、历史方案和设计资格/执行资格分离。

用户报告：逻辑斯蒂切换后无法选择合法驱动；辅助资料无明确入口；部分方案输入输出空白；未配置却检查通过。

## 入口与已核实问题

- `methods.js → schema-fields.js → method-picker.js → /designer/validate`：前端参数选择未表达逻辑斯蒂轴与单位依赖，1.5角色放开后可把叶面积选作时间驱动。
- `wizard.js → modeling.inputUsageRows`：只投影普通观测变量，原生制品/数据集输入没有展示；非通用回归训练的标签会被错误放入研究输入。
- `wizard.check → validation.check_definition → compile_plan(for_execution=False)`：待配置配方跳过请求校验，结构通过的提示没有区分配置尚未完成。
- `study_templates.template_view`已有准确原生资料说明及输入策略，页面尚未用来展示设计步骤。

## 约定

1. 参数候选遵从准确Schema及科学合同。逻辑斯蒂根据轴筛选天数/积温；缺失时明确提示需要何种单位，不能替用户发明或改写指标。切换轴后刷新候选并清除不合法旧驱动。
2. 普通观测按真实节点用途分为因素、目标和未参与资料。驱动仍为模型输入，训练所需目标和最终计算成果分别展示。未选模型时保留用户选择用途。
3. 原生数据集、影像及参数包按真实外部端口显示名称、用途、来源状态；采用模板提供的指标明细可读但不冒充当前目录已接通来源。
4. 未参与资料说明其由添加入口采用、尚未用于计算，提供明确调整/移除路径；无需另造一份辅助变量目录。
5. 设计组合可以包含待接通来源和未部署制品；缺少必需参数的“待配置步骤”不能等同完整检查通过。完整检查和正式保存复用服务端规则，定位到节点/端口/参数。编辑过程保留未完成草稿，不删除旧方案。
6. 模板预填且未编辑可以通过，但检查必须列出真实已采用的资料及成果，不能用“按组件合同”等泛称掩盖空白；无数据值不等于没有输入定义。

## 验证方式

先新增失败用例复现，再实现：全部模板的02/03非空且对应合同；全部可设计模型的端口展示；逻辑斯蒂模型替换与轴切换；自定义资料/目标采用；待配置请求检查及正式保存拒绝；历史模板和合法计划来源仍通过。前端真实DOM、Python权威规则及隔离数据库保存回读按调用链验证。本地预览更新并保留原隔离库，不自动发布生产，不启动海豚研究任务。
