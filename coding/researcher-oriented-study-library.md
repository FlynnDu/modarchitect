# 从研究人员出发重组研究方案库

2026-11-12。用户纠正：研究方案是对外使用的研究产品，不能把程序验收案例或整份勘察评分直接当成方案入口。旧项目已要求将勘察能力拆成多个可单独采用的方案。

## 研究人员需要决定什么

1. 研究问题与假设：研究什么关系、比较什么条件，或希望预测哪些量。
2. 研究对象与范围：地块、作物/品种、生育阶段、日期、观测单位、处理与独立试验单元。
3. 数据与方法：选择系统已有指标及合格数据来源；按数据形态选择方法，了解方法假设。
4. 验证与结论：留出哪些实测、评价什么偏差、数据覆盖是否足够；明确条件信号、模拟值与实测结论的区别。
5. 成果与复用：得到指标表、条件分析、模型情景还是可继续预测的模型；结果能否接入下一个研究。

入口因此是研究问题，不是算法列表、组件列表或某个历史地块的编号。算法在适用方案中选择。研究方案和示例数据分开描述，使用示例时明确标识，不把它称为用户当前地块的研究。

## 勘察能力拆解

| 独立研究方案 | 研究问题 | 数据与计算 | 结论边界 |
|---|---|---|---|
| 生育期低温与霜冻条件分析 | 近期是否出现需关注的低温？ | 合格日最低温 → 同一时间窗 → 原低温规则 | 条件暴露，不确诊冻损 |
| 生育期高温条件分析 | 近期高温达到什么程度？ | 日最高温 → 同期窗口 → 原高温规则 | 条件暴露，不确诊热害 |
| 降雨不足与水分供应条件分析 | 近期降雨是否不足，是否需要补充水分证据？ | 合格逐日降雨 → 完整窗口 → 原少雨规则 | 不把少雨直接认定为根区干旱 |
| 强降雨与积水条件分析 | 近期降雨是否达到需要排水核查的条件？ | 合格逐日降雨 → 原多雨规则 | 不替代地形、排水与积水实测 |
| 温湿条件与病害风险分析 | 温湿环境是否满足需要田间核查的条件？ | 日温度、降雨、VPD → 原病害气象规则 | 不等于已发生病害 |
| 耕层土壤理化特征分析 | 当前数据能说明哪些土壤特征、支撑哪些土层？ | 同来源同深度的土壤属性 → 属性汇总 | 网格参考不冒充田间实测，不给无依据适宜性评分 |
| 植被指数时序变化分析 | 两期或多期影像的植被指数如何变化？ | 合格指数成果 → 时间排序 → 差值与覆盖 | 不凭两期数据训练生长预测模型，不重做无原始栅格的空间分割 |
| 作物生长与水分限制分析 | 既有生长模拟中水分限制与冠层/生物量如何变化？ | 同模型同季逐日状态 → 指标时序与关系 | 模拟情景分析，不冒充实测缺水诊断 |
| 产量形成与干物质积累分析 | 模型情景中的储藏器官与地上干物质如何形成？ | 同一情景的逐日干物质与物候 → 过程分析 | 不宣称实际收获产量或品质 |

土壤、气象、植被、生长和产量方案分别采用自己的输入、方法和产物，不统一调用整份评分后筛选章节。可在后续综合研究中按准确产物连接。

## 论文方向与现有方案

- 保留多因素多目标生长预测、历史趋势与环境因素预测、观测汇总、温室耗水对照。
- 冠层温度关系研究在表格数据下选择 RF/XGBoost/GP；时序预测与网格时序预测分别采用相应输入。避免五张只写算法名的方案卡片。
- 真实论文样本尚缺时，示例数据只解释方法和交互，不声称复现论文精度。

## 实现要求

- 公共页面显示研究目的、数据要求、方法、成果、适用条件。历史地块编号、封存、制品摘要、接口与组件代码留在后台追溯，普通研究页面不显示这些信息。
- 目录采用研究问题分类；参数属于方案配置，数据来源单独展示。允许在批准的方法 Schema 内调整研究日期等参数。
- 保留此前准确模板及运行的历史读取，不改写旧模型与旧记录。当前公开目录不再展示案例评分复跑卡片。
- 扩展原生模板执行以分开批准的数据输入和可编辑研究参数；禁止改参数时偷偷更换来源或把上传数值当成已接通第三方数据。
- 气象规则复用旧权威科学模块；新增通用指标过程分析独立计算实际指标序列，保留单位、值性质与不足样本提示。

## 验收

研究人员能按问题选择独立方案、看懂输入到结果的流程、修改允许的参数、保存重开并运行。九个勘察子方案独立计算，不依赖整份评分。页面不出现历史案例编号、封存、工程验收、SHA 等开发术语。既有预测模型继续预测，历史模板仍按原版本读取。科学负例、来源资格、隔离和真实调度分别验证。
