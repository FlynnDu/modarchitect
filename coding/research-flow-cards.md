# 研究方案卡片流程与 API 核对

2026-11-12。依据用户提供的同一流程左右两张图，先核对 249 在线 OpenAPI、组件和输入目录，再沿路由、运行合同、调度、数据库、前端调用和已有测试核对。

## 结论与当前范围

现有接口能保存研究方案及组件连接，提交整次真实计算、查询结果并登记支持复用的训练模型，尚不能完整支撑图中的逐地块连续研究。

| 图中阶段 | 当前事实 | 缺口 |
| --- | --- | --- |
| 地块输入 | 有固定来源目录、选地合同、方案输入检查 | 输入检查明确返回 `data_available: null`；没有各地块天气/作物/土壤/管理实际齐备矩阵 |
| 参数与适配 | 有准确组件版本、请求参数校验及方案修订 | 没有可独立分配的作物/土壤/地点参数版本、逐地块科学适配与标定成果采用流程 |
| 地块实例 | 有整份方案的真实运行、调度身份和失败信息 | 没有地块子实例、部分启动、缺输入等待、补齐复检与按日研究调度 |
| 模拟产物 | 完成后保存组件输出和运行结果 | 没有逐日持续入库及按地块/日期查询的产物账本；当前采用目录无可执行 WOFOST 组件，生长过程研究分析的是已有模拟输出 |
| 验证与分析 | 部分预测表能按完整对象/日期与同单位实测计算误差 | 没有通用模拟实测配对账本、后到观测重评、跨地块比较及报告复核流程；当前报告适配明确拒绝 |

本次先交付用户追加要求的研究方案流程展示。用五张横向卡片表达“研究输入 → 方法与设置 → 研究执行 → 研究成果 → 评价与解读”，保留真实模型连接图。五张卡片是研究者的阅读阶段，不新增五个计算组件，不改变现有算法、模型状态、版本摘要与调度协议。分析、训练、模拟采用自己的描述，不把所有研究叫作机理模型或强行要求拟合曲线。

## 接口与职责

- 沿用现有方案定义、模板说明、输入目录和运行结果，不为五张卡片建立重复的流程接口。
- `GET /api/v1/workspace/runs/{run_id}/plan`：只返回该次运行实际采用的方案定义；不返回原始数据或 Worker 凭据。编辑草稿不能改写旧运行的解释。
- `research-flow.js` 负责卡片和模型连接关系的展示，标题、颜色、提示文案与布局不进入 API。来源资格、组件合同与可执行判断保持在服务端。
- 输入目录的“通道可用”不等于“本次数据齐备”；示例资料不等于当前地块实测。预览不展示通过、运行中或入库等假状态。
- 成果统计按已返回的公开输出项计数，不把不同形态的表行、指标数和文件数相加。评价配对逐输出与目标显示，避免合计重复对象而误报地块数。
- 运行中仅展示真实整次运行进度；结果完成前保持待产出。成功计算不等于通过独立科学验证。不会因图上的连线自动开放预测模型保存。

后端只补充准确运行方案读取，沿用现有身份和存储，核验封存内容摘要后只返回方案；数据库无需迁移。卡片详情使用原生 `details/summary`，有序列表保证阅读顺序，窄屏竖向排列；宽屏横向滚动并明确提示还有后续步骤。模型连接图仍按实际组件依赖生成，不用五步顺序替代数学依赖。

## 输入调整与启动判断

当前 16 个公开方案中，3 个采用观测表（其中串联方案只有合成演示资格），13 个采用指定资料；后者只有 9 个开放登记的日期、作物或指标参数。目录和详情新增最小 `input_policy`：`mode` 区分数据模式，`editable` 列出可调整对象。参数白名单复用既有 `editable_parameters`，普通方案读取组件 Schema。沿用 `execution_mode` 兼容旧调用。

策略由 `study_templates.py` 的权威函数根据准确模板、系统输入绑定和通道生成；启动继续使用同一固定来源验证、指定资料执行及参数白名单规则。前端不按方案名称判断，也不把“可编辑日期”误作“可上传任意输入”。预览策略不宣称当次数据已经齐备。启动前和方案卡片显示同一策略。

## 调用与更新

目录预览/采用、参数修改、保存与重开刷新方案视图；轮询计算时刷新准确运行视图。切换方案、编辑后到达的旧请求不得覆盖当前流程。失败应在流程区域明确展示并允许重试，不能保留上一方案的绿灯。打开非模板方案也可查看卡片和真实连接。

## 输入统计口径修正（2026-11-12）

用户指出联合预测方案的卡片显示“1 项输入”，配置表却显示多个指标。核对后是展示错误：卡片统计外部数据端口（1 张观测表），配置表统计表中指标（5 项），并非模型少接了四项数据。

- 外部指标从当前方案的观测配方与采集要求投影，卡片和配置表共用 `modeling.js` 中的 `inputUsageRows`。函数由原 `wizard.js` 移出，原导出继续保留，避免两个入口分别维护指标清单。
- 卡片主统计使用“输入指标”口径，同时明确“观测表”数量，列出已知输入和实测训练指标。原生资料没有声明观测列时显示“组输入资料”，不推测变量数量。
- 此串联方案训练时 5 项外部指标，预测时已知输入为定植后天数、NDVI、土壤体积含水率和气温；株高为实测训练指标。历史曲线估计株高是上游派生因素，不计入外部输入。
- 模型连接关系仍只有一个共享观测表节点，不把五个列名伪造成五个数据端口；节点标签明确表及指标数，详情保留名称。预测运行按该阶段需要/已封存的外部列显示，避免把训练标签误报为预测必填。
- 不新增 API 字段，不修改科学模型、组件合同、来源资格、运行或数据库。新增与删除外部指标后，两个视图根据同一方案即时更新。

验收：同一串联方案显示 5 项指标、1 张表、90 条记录，与配置表一致且不含上游派生量；直接多目标方案、预测阶段、多个表重复列和原生资料口径不混淆；新旧 JS 行为回归，以及 249 实际页面读取与编辑更新。

## 内容清单与评价分支

用户进一步要求卡片直接列内容，避免通用解释与建议占据主体。默认面展示指标及单位、真实方法参数、观测记录数和运行成果；适用范围、来源政策及长说明放入明细，移除每张卡片重复的“研究概况”和“建议”。

支持时间留出的训练方案按“研究输入 → 数据集 → 模型训练 → 预测成果 → 时间留出评价”展示。数据集到评价增加独立的虚线，表示训练截止之后的实测标签直接用于对照预测值；这条分支复用现有执行器的时间留出评价，不新增虚构的计算节点或数据切分。

当前联合预测示例实际 90 条记录（2026-04-01 至 06-29），历史拟合 45 条、后续回归训练 25 条、时间留出 20 条，以共享 `dataPeriods` 根据准确记录计算，禁止从日期跨度推测缺失记录。独立地块验证、开发验证三分法和数据集版本并未实现，不显示示意图中的独立地块或样本数。

当前提交记录在客户端保留一份与运行身份绑定的快照，供正在查看的运行显示分段数量。打开其他历史运行时仅使用该运行已有的输入行数和评价统计，缺少统计则不补造。API 不增加 UI 或统计字段；Python 和执行合同不改变。真实组件关系图继续展示既有分支和数据交接。

## 最小验收

1. 16 个公开研究、双目标训练及串联方案都能展示五阶段，连接图保留实际计算节点和边。
2. 预览不保存；修改研究日期后流程显示新设置，保存重开一致。
3. 缺通道显示未接通，数据未知不变成已齐备；示例明显标识。
4. 实际运行状态、结果项数、逐目标配对来自获权运行；成功但缺评价不得显示验证通过。
5. 另一工作区无法读取私有方案或运行流程。旧运行继续解释自己的版本，不受草稿修改影响。
6. 249 上采用、保存、重开、真实计算与卡片更新完成在线验收，保留既有训练及预测行为。浏览器原生视觉验收与 DOM/HTTP 验收分别记录。

## 后续完整业务验收

完整实现图片业务还需要研究实例与逐地块就绪、参数分配、模拟执行、持续产物和评价快照等领域能力。由同一研究总览接口汇总这些权威状态，前端不各自推断。验收用三个已授权真实地块：两个资料完整、一个缺土壤；仅启动前两个，补齐第三个后独立启动；按地块、日期和指标查询模拟记录；配对合格实测并生成可复核分析。图中的 312 条与 24 组必须先定义记录口径，不能作为固定演示数写入接口。
