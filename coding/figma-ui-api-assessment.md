# SONO 原型与 modarchitect 架构 / API 对照评估

2026-11-12。只读评估，不修改产品代码、数据库、设计稿或部署。

后续实施：[运行通用化首批改造与实际验收](runtime-generalization.md#2026-11-12-实施与验收结果)已部署 249，解决非训练运行及节点级用途的基础合同。本文保留改造前的评估事实，完整原型的其他业务缺口继续适用。

## 结论与读取范围

**当前后端能支撑一个有限范围的建模闭环，尚不能完整实现这份 UI 所表达的研究流程；整套 SONO 平台还需要其他业务服务。** 单一权威组件图、准确合同、不可变方案版本、封存输入、独立调度及训练模型制品可以保留。主要缺口是研究语义和应用服务，不是页面样式或接口名称。

[用户提供的原型](https://www.figma.com/proto/csgZSYv1g00TB16NEGwjgl/SONO?node-id=669-4523&page-id=222%3A2362&starting-point-node-id=269%3A2548) 的文件键为 `csgZSYv1g00TB16NEGwjgl`，目标节点 `669:4523`，起点 `269:2548`，画布页 `222:2362`。

浏览器读取到：模型配置的第 2 步、五步向导标题、科研工作台、科研助手阶段报告及入口页面。关键设计包括：字段在不同研究关系中有不同用途、区分训练和应用所需输入、按来源准备数据、算法与评价约定、复核与版本生效。示例目标是样方指定日平均株高，采用土壤含水率、NDVI、LAI、日均气温，列出随机森林模板及灌溉处理、品种分组。工作台展示团队模型/地块/采集、逾期或未对齐的数据、独立测试结果；报告展示版本表现变化与验证记录关联。

用户澄清公开访问后，已再次匿名浏览，补充读到模型选择页的训练、直接识别、非训练表型分析、模拟/可选标定、自定义框架等不同任务入口，以及 WOFOST 模拟 LAI 的固定来源用途。来源、评价、版本配置的具体表单仍未通过原型导航到达，不认定已经完整读取。详见[公开原型复读记录](figma-public-prototype-observations.md)。

**访问方式与限制：** 用户提供的是无需登录的公开原型，已经通过匿名原型浏览器读到页面，应继续按可见页面和原型导航查看。Figma 连接器的会话、源文件元数据和节点截图接口另外返回编辑访问权限不足；这只限制结构化源文件读取，不能据此要求用户为查看公开原型授予 Editor 权限。完整原始节点树不是本次浏览原型的前置条件。此前没有覆盖全部画板，也未逐一验证所有按钮的跳转和提交；浏览器读取报告中部分交互是可见控件的预期行为，不作为功能已经连通的证明。以下判断只引用实际读到的内容，不推断其他画板。

## 当前事实基线

本地应用生成的 OpenAPI 与 `http://127.0.0.1:8000/openapi.json` 只读比较：均为 40 个路径、48 个操作，路径/方法集合相同。接口存在不等于已配置外部身份、真实数据或执行制品。详细事实清单见 [API 能力核对](figma-api-current-capabilities.md)。

- 已有完整图的节点、端口、连线、参数及布局保存，草稿修订冲突检测、检查、不可变方案版本。五步表单可以编辑同一份方案，不需要另建一份独立配置。 [方案服务](../modarchitect/designs.py) · [组合合同](../modarchitect/contracts/model_center/components.py)
- 已有标准输入目录及准确来源校验、个人工作区保存、训练、结果、模型登记和预测；验证证据包括真实海豚执行。 [输入规则](system-input-components.md) · 验收记录
- 当前在线新设计目录返回 8 个计算组件，其中 5 项声明本部署执行可用；不包含随机森林。输入目录 63 项，但当前工作区仅 4 项标准人工 `field_season` 输入有通道。不能把全部目录画成可直接取数和训练。 [目录](../modarchitect/catalog.py) · [输入来源](../modarchitect/system_inputs.py)
- 个人工作区使用签名 Cookie，企业草稿/发布使用业务凭据及企业委托。二者不是完整的统一企业研究运行入口，也不是团队共享权限。 [工作区身份](../modarchitect/runtime/workspace.py) · [企业入口](../modarchitect/routes.py)

## 对照五步设计器

以下按模型配置侧栏表达的五类研究意图整理。它们不等于已核实的外层五页跳转状态机；没有读取到的配置表单不推断具体字段。

| 原型表达的能力 | 当前可复用内容 | 判断与实际缺口 |
|---|---|---|
| 1. 研究目标、成果、对象和时间 | 名称、问题、目的、变量、评价目标、图输出；部分科学对象合同 | 部分支持。运行观测只按地块/作物/种植季与业务日构表；缺样方目标任务及预测起报时点、目标时点等完整应用合同。 |
| 2. 输入与建模关系、训练/应用用途 | 多个变量、多个回归目标、组件图及输入参数 | 部分支持。变量角色是全局单值；一组回归特征供多个目标共用，缺每个目标/候选的用途关系和训练/应用可用性声明。 |
| 3. 固定来源与处理 | 输入目录、准确来源版本、属性 Schema、方法、来源封存 | 部分支持。天气、土壤、平台分析、物联网真实取数未接通；未实现通用缺失处理、跨尺度汇总和对齐质量状态资源。 |
| 4. 按能力选方法、配置评价 | 准确组件 Schema、线性训练/推理、历史生长趋势串联、时间后段误差 | 不足以覆盖示例。随机森林未登记执行；类别分组、独立分组切分、完整独立评价和报告中的 R²/版本提升比较未实现。 |
| 5. 保存、复核、版本生效 | 草稿、发布后冻结版本、成功训练模型制品 | 部分支持。保存模型不等于评价通过或生效，缺候选/复核/通过/生效/退役的业务转换及证据绑定。 |

### 三处会直接影响数据含义的缺口

**同一字段的不同用途必须附着于具体研究关系。** `Variable.role` 是单个字符串；当前回归请求是 `features[]` 与 `targets[]`，多个目标共用特征集。一个字段在候选 A 是目标、在候选 B 是因素时，不能仅修改全局角色。建议变量保留目录定义，在目标/候选/节点的绑定中声明用途及训练、推理阶段。沿既有方案中“一份权威图 + 候选输出引用”的方向实现，不再复制一份会与图分离的参数配置。 [变量合同](../modarchitect/contracts/research/variables.py:21) · [回归请求](../modarchitect/contracts/runtime-components-v1.json:375) · [既定方向](agricultural-model-designer-assessment.md)

**样方平均株高不能映射成现有地块表中的一个同名数值。** 标准 `height_cm` 是点位，`plant_height` 是单株；运行表的对象只有地块、作物、种植季，编译器还明确拒绝非 `field_season` 数值输入。需要科学对象层级、观测/试验单元、从单株或采样点到样方的聚合规则与来源链。不能靠改名称或单位完成。 [运行观测](../modarchitect/runtime/contracts.py:27) · [适配限制](../modarchitect/validation.py:101) · [旧标准审计](system-input-component-source-audit.md)

**时间留出误差不能显示成独立验证或模型已生效。** 合同虽预留分组、留出单元和评价门槛，执行器现有评价主要按组件训练截止日计算后段 MAE、RMSE、bias、coverage。模型登记只检查训练成功，不执行独立评价复核和生效门槛。逻辑斯蒂组件内部的拟合 R²也不能替代报告所指的独立测试 R²。建议独立评价资源引用准确模型、预测、标签修订和切分；新评价不改写原预测和训练证据，生效操作检查已通过的准确评价。 [评价实现](../modarchitect/runtime/executor.py:70) · [模型登记](../modarchitect/runtime/store.py:348) · [评价合同](../modarchitect/contracts/research/evaluation.py)

### 复读补充：运行类型还不够通用

模型选择页明确区分训练、直接识别、非训练三维表型、模拟与可选标定。当前 `POST /api/v1/workspace/runs` 接收 `TrainingRequest`，另一个入口是引用已保存模型的预测；执行器在没有可复用训练状态时直接拒绝结果。因此，单纯新增一个非训练计算组件的目录定义，也不能让它通过当前运行闭环。这是运行合同和状态持久化需要扩展的内容，不是给页面增加一个模型类型选项即可解决。 [运行入口](../modarchitect/runtime/routes.py:119) · [训练请求](../modarchitect/runtime/contracts.py:82) · [强制模型状态](../modarchitect/runtime/executor.py:233)

应由版本化组件能力声明任务的输入、操作及产物要求，研究运行分别验证训练、推理、分析、模拟或标定所需结果。非训练分析不强制生成训练模型；训练任务才要求可复用状态，推理继续引用准确模型。仍使用同一权威计算图及调度、封存和回传机制，避免按每个 UI 模板复制一套执行服务。

WOFOST 模拟 LAI 也不能直接使用当前人工实测 `lai` 的绑定冒充。需要准确模拟来源/上游成果、固定模型版本和时点证据；值性质继续作为模拟因素传入，不能成为实测训练标签。

## 工作台与科研助手的服务边界

| 已读界面 | 当前 API 状态 | 应有归属 |
|---|---|---|
| 团队模型、科研地块、采集概览 | 当前主要是当前主体最近列表；缺团队范围汇总与完整分页筛选 | 研究服务提供受权研究统计，业务系统提供地块/采集统计，工作台聚合；不复制主数据。 |
| 周采集、逾期、等待输入、数据对齐问题 | 有采集要求和静态通道限制；没有已排程采集任务、逾期状态、逐项数据问题的服务闭环 | 研究规则产生要求，业务采集服务维护执行记录，研究服务消费合格观测。 |
| 运行处理状态 | 有整体状态和最终节点输入输出摘要；没有运行中节点状态、进度和实时日志 | 执行服务记录实际事件，对当前主体提供查询/事件订阅，不能把最终 receipts 当实时进度。 |
| 独立测试监测、版本性能改善 | 有单次运行误差，无统一独立评价集合和同口径版本对比 | 研究评价服务，固定样本、对象、日期、覆盖与度量。 |
| 对话生成阶段报告、关联验证记录 | 本项目没有对话/报告资源；带报告配置的方案目前被编译器拒绝 | 复用 SONO 若已有的对话及报告服务；调用受权研究 API，报告引用准确结果与评价。 |

上述是已见页面所需的能力边界，并不表示这些业务服务必须全部新建在 modarchitect。需要对照 SONO 主平台已有服务分配归属。

## API 改造方向（建议，当前尚不存在）

优先补齐上面的运行操作与产物合同，再落实以下研究业务能力。所有扩展均需保持旧方案、旧排队载荷和已保存模型的准确回读。

1. **先补研究合同和预检。** 在既有方案内表达目标/候选引用、输入用途、科学对象和评价任务。复用现有完整校验器，增加向导步骤的阶段校验、字段路径与阻断原因；未完成的草稿不获得执行资格。五步 UI 与组件图读写同一权威定义。
2. **接通研究实例与数据准备。** 实例绑定准确方案版本、授权对象/种植季及数据范围；准备动作返回来源级、变量级的可用/待采集/缺配置/不支持及证据。训练引用封存数据集或明确的标准人工记录，不能由前端自行拼造“已取到”的外部来源。
3. **补评价和模型生命周期。** 独立评价先有准确资源身份，再做比较、复核和版本生效。训练产物、方案版本与生效模型版本分开；只要计算完成就显示“已生效”会误导。
4. **补运行和页面查询。** 在受权运行查询上增加节点事件、可定位错误、取消与重试语义；为模型、方案、运行提供分页/搜索/状态摘要，工作台汇总由有权的服务端计算。内部 Worker 凭据和海豚凭据不进入前端。
5. **按目录接入第二种真实方法和真实农业数据。** 随机森林走现有组件模板、正反例、登记和隔离制品流程；按来源合同接入真实 NDVI、土壤和气象，完成点位/单株/样方适配与授权验收。界面能力读取目录，不写死“所有方法均可用”。

对外响应也需成为明确合同。本次检查的方案列表、运行详情及输入目录在 OpenAPI 中仍是 `object + additionalProperties`；前端无法从该规范取得完整的页面数据类型。建议按实际页面消费定义列表摘要、运行详情、来源就绪及错误响应，提供稳定错误码与字段/步骤定位。保留整份图的原子保存方式，按版本扩展业务合同；旧冻结方案和模型继续按原定义解释，不重写其角色、科学单位或摘要。

不需要为每个按钮建一个接口：切换步骤、画布排列、展开面板等可由前端完成；重命名或复制也应先核对现有保存/新建能否复用。只有共享规则、授权、持久化状态和执行动作需要后端决定。

## 建议的首个验收目标

以原型中的作物水分研究作为端到端验收，先明确该任务是同日估测还是未来预测，不能把二者共用一个含糊时间字段。随后用真实授权的样方/采样点、固定来源的输入与平均株高标签，完成五步保存、重开、执行、独立评价、候选版本复核和生效，并用生效模型执行新任务。每一项显示必须来自实际状态和准确证据。

如果阶段性只交付现有能力的前端，原型必须显示：支持的方法、实际科学单位、来源尚未接通、当前是时间留出评价、模型仅保存为候选。不能用静态数值填充团队概览、R²、独立验证或版本改善。

本轮没有修改后端，没有重跑训练或更改部署；证据来自指定原型浏览器读取、当前源码、既有测试/验收资料及本次线上 OpenAPI/目录只读核验。
