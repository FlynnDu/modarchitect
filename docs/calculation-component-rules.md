# 计算组件开发规则

2026-11-20。适用于内置和获准接入的计算组件。第 5 步展示版本化合同，业务校验与执行以同一份合同为准。

## 从设计稿提取的能力

| 设计稿特征 | 开发规则 |
| --- | --- |
| 当前方法、能力摘要、更换入口 | 声明准确组件、用途、可解决的问题和成果。目录资格、组件制品可用与本次数据就绪分别表达。 |
| 输入变量、预测目标、观测 | 声明端口的语义、类型、单位、采样对象、日期或空间对齐、来源性质及必填程度。每个请求字段声明绑定端口以及训练、预测、分析等使用阶段。观测范围从当次实际记录读取。 |
| 训练策略 | 展示划分方式与训练、验证两组比例。自动日期划分默认 80% / 20%，训练比例可按方案编辑，同一天记录在同一组。运行时以已封存观测确定边界，历史窗口按原配置执行。 |
| 评价指标 | 展示执行能力声明的指标及当前选中状态。回归留出评价支持 R²、RMSE、MAE 和平均偏差。恒定实测或只配对一条记录时，R² 返回空值。MAPE 须先定义零值与近零值口径再接入。 |
| 高级设置 | 用 JSON Schema 声明范围、类型、默认值和说明。组件仅声明真正消费的参数，请求字段按普通用途或高级用途展示。运行值和常量由平台绑定。 |
| 结果与预测 | 列出真实输出。训练组件声明准确的可复用状态、独立推理版本及最终预测表。训练配置可先保存，实际调度在发起研究时进行。 |

如果把设计稿的所有字段强制给每个组件，资料转换会被要求虚报训练策略，规则分析会被要求虚报可保存模型。采用公用合同加操作能力的结构。组件的注册类别仅用于查找，是否有训练、推理或分析能力由操作声明和实际合同判断。

## 所有新组件必须交付

1. **准确身份与操作。** 声明代码、修订、执行入口和支持的操作，根据合同与制品绑定摘要。变化通过新修订交付。
2. **端口和参数。** 通过准确输入输出端口与请求 Schema 描述依赖。给带来源约束的科学字段声明用途和阶段。由设计器生成表单，由 Worker 消费同一合同。界面按角色和能力渲染。
3. **成果和错误边界。** 声明成果的实际含义、空值或缺资料行为、科学适用范围及资源上限。输入类型冲突、错对象／日期、缺必需资料可定位并拒绝。
4. **可独立复跑。** 交付锁定依赖、准确制品、可复算输入输出、误差阈值及拒绝例。能按真实入口完成目录读取、接入、运行回执和历史版本回读。验收要求见[组件架构约束](../coding/model-designer-migration.md#组件架构约束)。

训练组件还须声明实测标签与因素或驱动、模型状态端口、关联的准确推理组件、验证预测表。验收证明预测复用原状态，直接提交预测所需资料即可。转换组件验收输入继承、来源和对齐。规则分析、模拟和标定组件验收真实操作和成果性质，按自身方法声明评价。

## 五个训练组件的固定行为与可调参数

共用数据资源的展示顺序为输入、目标实测、观测及完整性。所有方案先向组件提供符合要求且按对象与日期配对的观测，再按业务日划分较早训练与较晚验证。预测时仅取得已训练模型申明的输入。回归指标使用同一份留出配对记录，以目标原单位报告误差。

| 计算方式 | 实际数据需求 | 固定设置和可调参数 | 成果与适用范围 |
| --- | --- | --- | --- |
| 多变量线性回归 | 连续已知因素及目标实测，训练矩阵需可辨识 | 普通最小二乘，始终拟合截距，原单位，无正则化。可改因素、目标 | 截距、系数和预测表。不同单位的系数需谨慎比较 |
| 逻辑斯蒂日期曲线 | 同一对象的实际业务日期及一项实测目标 | 三参数曲线，按地块作物种植季拟合，平台日期驱动。可选择实测目标 | 生长上限、增长率、拐点与后续日期预测，限已拟合对象 |
| 随机森林回归 | 多个因素、实测目标 | 64 棵树、深度 8、最小分裂样本数 2、每次分裂考虑全部特征。可改随机种子 | 树模型和预测。当前不输出特征重要性。新增该成果需声明方法和对象范围，优先用留出记录复算，并明确相关特征会影响解释 |
| XGBoost 回归 | 多个因素、实测目标 | 64 轮、深度 4、学习率 0.08、CPU 直方图。可改随机种子 | 提升树模型与验证预测。单组件的固定限制随准确版本登记 |
| 高斯过程回归 | 多个因素、实测目标。当前训练规模上限 1000 行 | 固定 RBF 核，长度尺度 1，噪声项 α 为 0.01，仅从训练集拟合特征尺度并归一化目标 | 核模型与点预测。当前协议不输出预测区间；随机种子兼容字段不作为可调项 |

## 机理模拟与研究方案采用

机理模拟选择 `operation=simulate`。资源包括气象驱动、土壤剖面、品种参数版本、初始条件、播种／出苗日期、灌溉等管理事件。模型 Schema 仅暴露准确版本实际支持的情景与水氮模式。模拟期是情景输入，由研究应用或运行上下文提供。训练比例、Epoch、Batch Size 等字段属于相应训练方法。

WOFOST、APSIM 的情景定义与参数来源按准确版本接入。模拟 LAI、模拟产量和实测是不同的来源性质，须按对象、日期或收获期、单位及采样口径配对，再计算适用的指标。可选标定须另声明 `calibrate` 操作和未参与标定的验证范围。模拟时序、情景统计和观测对照是各自可追溯的成果。 [WOFOST 官方说明](https://www.wur.nl/en/research/products-services/wofost-world-food-studies) · [APSIM 官方文档](https://docs.apsim.info/docs/)

仓库目前保留 WOFOST 历史成果分析和蒸散、水量核算等组件。WOFOST 和 APSIM 列为待接入作物机理模型，缺准确可执行制品、品种和情景合同、实际模拟与观测对照时不得采用至新研究。计划中的模型只显示在方法类别的接入清单。研究目录候选也按实际操作验收，机理模拟方案的采用资格由驱动可得、已登记模拟制品、情景可复跑及声明成果决定。已经满足训练合同的 8 个方案继续走原有训练采用与预测入口。

## API 对接

- `GET /api/v1/model-center/research-methods` 统一声明 `families` 和 `items`，候选的 `planned` 状态独立于组件。实际方法含 `operation/component/name/relationship/settings/configuration/outputs/execution`。
- `settings[]` 的 `code/name/value` 表示准确版本的固定行为。可编辑字段按 `configuration.parameter_schema` 声明，带默认值的可调项在 `advanced_fields` 显式列出，`runtime_fields` 由平台绑定。更改固定设置需新修订或交付真正可用的参数合同。
- `inspection` 按当前方案提供资源、用途、参数、成果、预测和评价。每类均返回相同顶层键。没有相应能力时预测和评价为 `null`。真实运行单独返回数据预检和实际成果。
- 第 5 步将输入变量、预测目标分别展示，并按 `inspection.evaluation` 提供训练策略与指标的编辑入口。设置写入方案的 `evaluation.training_percent` 和 `evaluation.metrics`，由运行读取封存值。训练方案的方法选择从可输出复用模型的步骤中选择，保留已定义的数据配对与派生步骤。
- 训练方案的当前模型标题与方法选择使用同一节点规则。实际为模型提供输入的上游节点在配置页和选择弹窗中显示为「资料处理」，如卫星 NDVI 配对和平台日期换算。

## 现有目录核对

逐项核对登记合同、请求 Schema、操作声明、输入输出和训练状态依据。共 32 个准确版本，29 个允许新设计组装，含 1 个自动日期转换。每项界面去向与缺口见[逐项审查](../coding/research-method-design-20261120.md#全目录审查标准)。

| 核对结果 | 准确组件 |
| --- | --- |
| 满足通用训练面板的 5 项 | `historical_logistic_training@1`、`multivariate_linear_training@1`、`random_forest_training@1`、`xgboost_training@1`、`gaussian_process_training@1`。具备因素或日期驱动、实测标签、状态、验证输出和独立推理。 |
| 推理子组件 5 项 | `historical_logistic_predict@1`、`multivariate_linear_predict@1`、`random_forest_predict@1`、`xgboost_predict@1`、`gaussian_process_predict@1`。声明状态输入和预测端口，由模型入口调用。 |
| 转换 3 项 | `research_forecast_feature_join@1`、`sentinel_ndvi_features@1`、`research_calendar_axis@1`。声明配对或派生资料，作为研究步骤。 |
| 分析 10 项 | `research_descriptive_statistics@1`、`convlstm@1`、`gaussian_process@1`、`lstm@1`、`random_forest@1`、`survey_assessment@4`、`xgboost@1`、`research_weather_conditions@1`、`agronomic_indicator_analysis@1`、`catalog_weather_conditions@1`。用真实分析输出描述能力。固定案例如需进入普通训练选择，应交付自有资料接入、状态和独立推理的新修订。 |
| 模拟或核算 3 项 | `greenhouse_crop_et_daily_comparison@2`、`greenhouse_reference_et_daily@3`、`greenhouse_weighing_water_balance@2`。保留物理计算、对照或水量核算。 |
| 早期合同 6 项 | `logistic_growth_curve@1–4`、`multivariate_linear_regression@1`、`historical_logistic_forecast@1`。前三个曲线修订仅用于历史解释，其余可按原合同组装。采用可复用训练合同进入普通入口。 |

## 验收风险

- 日期切分验证的是给定因素下的较晚观测。跨地块、跨季节和预测提前量需要独立试验。训练过程中的特征拟合、窗口聚合等处理也要排除未来观测。
- R² 在恒定参考值等情形下需报告不可计算。MAPE 遇到零值或接近零的观测无法直接解释。指标契约需要明确配对、缺失、分母和分组。
- 资料通道已登记只表示具备采用条件。样本量、日期覆盖、实际授权和制品就绪到运行时校验。
- 交付自定义学习组件的成本包括数据适配、制品隔离、模型状态兼容、可重复验收和历史回放。优先把已支持的模型和数据组合成新方案。

v0.4.0 定向验收通过 94 项 Python 行为测试和 130 项前端测试，覆盖当时的 8 套方案、统一面板、方法切换和窄屏展示。当前目录扩展见[目录扩展验收](../coding/growth-catalog-expansion.md)。真实取数、论文数据和生产调度按各自接入阶段验收。
