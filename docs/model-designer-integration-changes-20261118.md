# 模型设计器本期对接修改清单

2026-11-18。以下修改以 v0.1.1 的前后端对接说明为基线。

**沿用旧版调用编号、路由、服务 Key 和双边落库顺序。** 本期验收终点是「正式保存研究方案 → 按 ID 回读 → 展示同一修订的流程图」。之前已实现的列表、详情、配置检查、保存和回执转接可以保留。 [完整接口流程图](model-designer-api-flow.md)

## 前端修改项

**2026-11-19 追加更新：**资料、计算参数、成果和规则新增统一 `inspection` 响应，前端按类型和合同展示；分析方法不再套用训练流程。规范化检查统一使用 code/path/node/port/message，配置完整、操作兼容和本次执行分别判断。后端转接保留新增投影，原字段及保存摘要继续兼容。详见[v0.2.0 本次改动项 U1—U9](release-notes-v0.2.0.md)及[响应合同](research-inspection-api.md)。

| 编号 | 旧版正在开发的部分 | 本期改法与验收 | API |
| --- | --- | --- | --- |
| F1 | 基础信息、选择模板 | 页面保留方案名称、负责人、研究目标、模板版本。负责人传业务用户 ID 字符串 `definition.responsible_user_id`，姓名由业务系统显示，历史方案允许空。模板版本读取准确模板，保留原定义的模板引用。自定义显示“自定义”。作物及本次研究对象留到发起研究时绑定。 | 02、09—12、14 |
| F2 | 指标和用途配置 | 分成「研究资料与候选因素」「目标指标与预期成果」两页，共用同一份定义。按 `variable.code` 双向检查重复，已选项在另一页显示原用途并禁用。每个指标提供只读详情、来源及提供方式。允许选择已登记的待接入指标，保留准确绑定。普通研究移除自由编辑指标和通用处理对照。分析及模拟按实际资料和成果显示，无需强制填写预测目标。 | 02—04、06、10—12 |
| F3 | 计算方法、日期类参数 | 按准确版本读取参数和端口，分别显示设计资格和实际运行状态。方法需要 `day` 且缺合法驱动时，按 06 声明接入 `research_calendar_axis@1`，只读显示“平台观测日期（自动使用）”。日期按实际观测的 `business_date` 计算。逻辑斯蒂 V4 每个拟合节点只配置一个目标，多目标用多个节点或选择支持多目标的方法。模型未采用的候选资料明确标示。 | 05—08、09—10 |
| F4 | 校验页和保存动作 | 配置区轻量检查，最终「检查与确认」从当前草稿预览动态流程。09 生成文件，10 查完整定义。HTTP 200 且 `valid=true` 才能继续正式保存。错误用 `issues[].path` 定位到分区，用可选的 `node/port` 高亮出错节点。只点击检查时停留在确认页。 | 09—12 |
| F5 | 采样计划、模型初始化 | 本期保存流程在「检查与确认」直接提交。采样对象、周期、频率、时间及采集人留给之后「应用方案 / 发起研究」。从当前保存路径移除采样计划确认和模型初始化的前置跳转。 | 11/12 |
| F6 | 保存后的流程图 | 用 14 回读 `configuration.definition`，按实际资料、组件、成果与依赖渲染。卡片数随方案变化，串联和分支来自 `bindings`。缺少已发生的观测、评价或模型发布记录时，显示相应待办或预期成果。 | 14、06 |

## 流程图应替换的三处

1. 入口保留公共模板（01 → 02）、自定义、导入（18）、编辑已保存方案（13 → 14），另明确“仅查看”从 13 → 14 直接进入流程图。
2. 设计阶段标明两页共用指标目录，由 03 → 04 采用，再用 05 → 06 设置方法。07 只在切版本时调用，08 只在需要串联时调用。确认页先预览和检查，可返回修正，也可在通过后正式保存。
3. 保存后由业务后端登记关联，再用 14 回读并展示动态流程。采样计划、初始化、创建海豚任务、训练及发布属于后续应用。 [按 API 编号展开的 Mermaid 流程图](model-designer-api-flow.md)

## 联调验收范围

- 先用一份公共模板和一份自定义方案，各走一次检查、正式保存与 14 回读。自定义至少覆盖一个目录指标、一个目标或明确成果及真实模型连接。确认可以在未绑定地块、样点、频率及未上传当次观测时保存。
- 对照两种负例检查页面定位。用已选同一指标在另一页重复添加，界面应拦截；通过接口直接提交缺来源绑定或缺必需方法参数的配置，10 应提示具体位置，11/12 应拒绝落库。
- 对照简单分析和串联方案检查图。简单分析按实际输入、分析和成果生成，串联按实际依赖展示；没有实测或评价时，可辨识待运行状态。
