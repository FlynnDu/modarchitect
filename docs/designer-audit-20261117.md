# 研究设计器专项盘点 · 2026-11-17

## 结论与范围

本次问题跨越参数表单、输入用途投影和完成性校验，不能只修一张页面。检查覆盖20个公开研究主题、2个可选择的方法变体（合计22份当前方案定义）、28个当前可设计基础模型，以及自定义入口、配置检查和正式保存边界。

研究方案保存的是可复用设计。实际地块、作物、观测周期、当次数据与运行资格仍在发起研究时核验。模型未部署、来源尚未接通与模型参数尚未填写是不同状态。

## 四个问题的原因与修复

| 用户遇到的问题 | 核实原因 | 当前处理 |
| --- | --- | --- |
| 换成逻辑斯蒂后反复报驱动单位错误 | 旧合同表单缺少轴与单位联动；1.5方案放开节点用途后，叶面积等指标也进入时间驱动候选 | 天数轴只列day，积温轴只列deg_c_day；换轴刷新候选并清除不合法旧驱动。缺资料时明确说明所需单位；服务端科学校验继续保留 |
| 不清楚“辅助与其他资料”如何添加 | 该分组混入了历史模型正在使用的时间驱动，也没有说明未采用资料的来源和操作 | 历史驱动归入有效输入。真正未被计算采用的资料标为“尚未用于计算”，说明来自添加入口，提供配置用途和安全移除；仍被参数引用时禁止直接移除 |
| 有的方案看起来没有输入或没有输出 | 页面只处理普通观测列，没有呈现原生数据集、影像、参数包；训练目标和成果文件混用显示条件 | 02按真实外部端口列出资料、来源状态和消费方法，普通指标保留固定来源；03列出真实目标及准确输出成果。原生示例中的目标通过现有input_requirements.kind=target明确投影 |
| 看起来什么没填也检查通过 | 部分模板本身已预置完整示例；另有待配置request被服务端跳过，纯空格名称也能通过 | 预置资料与参数明确列出，合法模板无需重复填写；缺方法参数返回incomplete_configuration，正式保存同样拒绝。空白名称、问题、缺模型、缺成果与错误参数由相同规则拒绝 |

## 平台规则

1. 指标定义、单位、来源和采样尺度继续由目录固定，不通过改单位让模型勉强接受。
2. 设计时可以引用已登记但未接通的数据来源及未部署的方法。真实数据接入缺失在运行时拒绝，不伪造数据或制品。
3. 待配置的**方法参数**可以在编辑草稿保留，但不能通过完整检查或正式保存。参数已完整、只缺获取适配的准确类型资料仍可作为未来设计保存。
4. 09生成草稿不等于检查通过；10检查完整定义，11/12在写入前复验。incomplete_configuration使用原issues结构定位path/node/port，没有新增按页面命名的API。
5. 模板预置配置允许直接通过设计检查。检查成功只说明当前定义成立，不能解释为本次已取数、已训练、可以预测或已经有科研有效性证据。
6. 所有方法都展示真实成果。分析、拟合、模拟及训练的成果不同，页面按已声明能力说明是否产出可复用模型，不再统称“训练后可保存预测模型”。

## 结构与兼容

- `request-schema.js`集中解析准确表单属性、历史逻辑斯蒂声明及变量候选，模型切换、用途投影和参数表单共同采用；该模块不依赖页面渲染。
- `modeling.js`解释节点用途、外部资料和成果；`wizard.js`呈现研究步骤；`schema-fields.js`仅生成参数控件。
- `validation._requests`保留唯一完整参数检查入口，检查API与正式保存共用。已登记组件合同、版本摘要、历史方案和数据库结构未被重建。
- 输入资料缺接入与参数未配置分开处理；未增加可由客户端伪造的“已通过”标记。
