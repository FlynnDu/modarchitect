# 研究平台规则

研究人员可以调整研究问题、数据与方法，但每次调整都须满足输入、组件与成果的合同。平台判断在服务端集中执行，页面显示同一结果。

设计与执行分开：全部已登记指标和可组合模型可设计；未接通来源保留planned_source绑定，未接入资料保留准确类型的deferred输入。正式保存验证结构、参数、科学单位和准确引用，不要求当次数据或执行实现就绪。运行继续核验取数、适配、制品和授权。design-saves保存前重复只读检查，非法设计返回同一issues且不落库。见[API闭环](../coding/api-design-loop.md)。

## 输入调整

以下是不同操作，不能用一个“可编辑”开关混在一起：

| 调整对象 | 允许的方式 | 运行前必须满足 |
| --- | --- | --- |
| 数据记录 | 新增、删除、替换观测行 | 非空、完整对象和日期唯一、列与有限数值合法 |
| 研究输入 | 从系统目录新增或移除指标与来源 | 使用准确版本、定义、单位、观察尺度、来源及取数属性 |
| 因素 | 新增、删除、改变其参与的方法 | 组件支持该数量与形态，实际输入中存在所选因素 |
| 目标 | 新增、删除或改选要解释/预测的指标 | 组件支持多目标时分别绑定；训练目标必须有合格实测，不能删空必需目标 |
| 分析指标 | 从该资料和方法支持的指标中增选或取消 | 不得选空或越出声明范围，不把筛选指标当作新增底层资料 |
| 参数 | 按组件 Schema 或指定方案白名单修改 | 日期、取值及引用合法；改参数不改变输入来源资格 |

系统指标定义和来源含义不能由用户随意重写。缺取数通道或科学单位适配时拒绝实际运行；上传一个同名数值不能替代该来源。历史私有变量、合成演示、上游派生指标各自保留性质。估计、模拟和预测结果可以按兼容合同进入下游，但不能充当实测训练标签或验证真值。

第三方来源通过独立采集任务形成不可变快照。研究请求只携带必要的 `source_snapshot_ids`，服务端核对准确绑定、单位、对象、日期和值；不能用手填列替代平台取数。新采用使用当前批准来源，既有绑定和准确幂等重放保留原来源，实际执行仍需接入登记有效。采集由 DolphinScheduler 调度，预检不下载数据；旧组件输入不增加来源元数据。实现与范围见[第三方来源验收](../coding/deployments/modarchitect-249/source-inputs-acceptance.md)。

当前研究目录中，2 个标准观测方案可采用同来源同单位的自有记录，1 个观测串联方案仍仅具备合成演示资格；13 个指定资料方案不允许更换底层资料，其中 9 个开放登记的研究设置。以准确方案返回的 `input_policy` 为准，不按名称判断。复制或另建研究也必须重新采用合格来源和可执行组件，不能通过去掉标记绕过批准资料约束。

## 输入、连接与成果

1. 每个必需组件端口都有明确输入。方法配置引用实际接入表中的因素、目标与驱动。
2. 上游输出接入下游时，语义、版本、形态、科学单位和时空对齐须相容；不隐式改单位、补日期或把模拟转成实测。
3. 计算依赖无环。五阶段卡片用于阅读，实际执行仍按模型连接图的依赖排序，允许合理的并行支路。
4. 公开成果来自真实节点的已声明输出。分析摘要、结果表、拟合参数和训练状态分别管理。
5. 训练只有产生可复用状态才允许登记模型。继续预测复用原状态与预处理；分析报告或一次留出预测不能当成可调用模型。
6. 评价按同对象、种植季、日期、目标和单位匹配合格实测，分别报告覆盖与误差。计算完成不等于验证通过，多指标配对数不等于地块数。

## 保存、检查与启动

未完成配置可作为草稿保留；保护来源和权限等约束仍需遵守。检查不创建草稿、版本或运行。实际启动重新检查准确修订、授权、来源、数据、组件操作和运行制品，成功后封存输入并提交真实调度。预检通过不保证后续仍获授权或资源仍可用。

历史运行解释自己的准确方案，当前草稿编辑不能改写它。修改输入后，页面回到当前方案视图，不沿用上次运行的绿灯或成果数量。失败、调度结果未知和成功分别显示，不用“已运行”概括。

## 最小 API 合同

`input_policy` 只有两个字段：

```json
{"mode":"user_observations","editable":["records","inputs","factors","targets"]}
```

`mode` 为 `user_observations`、`synthetic_demo_only` 或 `approved_dataset`。`editable` 表示允许进入调整流程的对象，不是无条件执行许可。普通方案参数按组件 Schema 配置；指定资料方案复用既有 `editable_parameters` 白名单，不在新字段里重复返回。未开放字段不得修改。

- `GET /api/v1/model-center/research-rules`：规则版本、标识及说明。
- `POST /api/v1/workspace/check-execution`：提交当前定义、操作以及需要的观测与数据性质；返回 `can_execute` 和 `issues`。
- 每条问题只有 `rule`、`path`、`message`。真实启动拒绝时保留原 `detail`，补充相同规则问题，兼容旧调用。
- `GET /api/v1/workspace/runs/{run_id}/plan`：只返回该次运行的准确方案定义，受工作区权限保护；不返回原始输入和执行凭据。

页面标题、颜色、布局和固定五阶段连线由前端维护。现有方案与运行接口可提供的内容直接复用。
