# v0.2.0 资料、计算与规则响应更新

2026-11-19。本次在 v0.2.0 基础上统一设计器与 API 的业务事实。准确组件、参数与科学成果仍按原合同解释。

## 改动项

| 编号 | 改动 | 对接方需要处理的内容 |
| --- | --- | --- |
| U1 | 新增统一 `inspection` 响应 | 按 materials、nodes、outputs、checks 展示资料、计算与规则，无需按算法名称分支 |
| U2 | 新增只读 `POST /api/v1/research/definitions/inspect` | 正文提交当前 definition，沿用服务 Key；响应类型公开在 OpenAPI |
| U3 | 检查、模板、草稿及版本详情附加投影 | 保留原字段和配置摘要；完整研究版本在发布和回读时返回一致投影，只有旧组合的历史版本 inspection 为 null |
| U4 | 统一问题定位 | 规范化问题为 code/path/node/port/message；旧 issues.type、issues.rule 保留兼容，未知 code 也可显示与定位 |
| U5 | 分开表达三类检查 | configuration 表示配置完整；operation 表示操作兼容；execution 表示本次实际执行资格。not_checked 与 unsupported 均不能显示为通过 |
| U6 | 提前解释多步骤操作限制 | 同一方案仍要求各节点支持当次统一操作；不兼容时定位具体节点，计划设计保存资格与执行资格分别返回 |
| U7 | 通用参数和资料展示 | 使用准确端口、Schema、来源状态、节点用途和成果；分析方法不再显示固定训练、留出评价和保存预测模型流程 |
| U8 | 编辑与异步反馈 | 参数写回同一份 definition；连续输入保留焦点；切换方案清除旧控件；迟到响应不覆盖当前方案；核对失败可重试 |
| U9 | 实际执行检查保持关联 | 方案或资料在检查/保存期间变化时要求重新检查，防止沿用旧检查结果 |

## API 响应及兼容

投影版本 `inspection.schema_version=1.0` 与研究方案 schema_version 分开。参数保留各方法自己的 JSON Schema，资料保留原始类型、科学单位、来源和采样尺度；原生受限资料只提供公开元数据。

现有配置检查仍返回 valid/compiled/issues；设计器检查仍返回 configuration/check。旧客户端可以继续使用原字段。新增字段不写入保存正文或冻结摘要，既有方案、固定版本和模型保持准确引用。未接通来源与未登记制品仍不能取得实际运行资格。

数据库迁移头仍为 0015，本次没有新增迁移。计算组件及科学成果负载保持各自的版本化合同。部署按准确提交和安装包摘要核对，避免只凭包版本号认定制品一致。
