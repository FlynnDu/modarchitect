# 原生温室计算的独立文件适配

只适配已冻结、单一 bundle 输出的纯计算合同。组件身份及合同摘要由构建时 `binding.json` 固定，入口继续调用准确原科学实现，不能从运行请求指定导入地址。

`vendor/` 是旧项目四个已核对源文件的原样副本。保留原作者、文件头和字节，摘要见 `sources.json`。三个设计节点共用这些科学实现，外部请求及上游成果按既有 Pydantic 合同校验。旧项目只读，部署不访问旧源码目录或业务库。

构建基础使用已批准 CPU 科学运行镜像的准确配置摘要，由构建方传入 `APPROVED_BASE`。该基础已含版本化合同及科学依赖，缺少新温室门面，因此在派生镜像中补入原样文件。每个节点的最终镜像独立登记。

正例复跑耗水三节点及相邻字节摘要，负例拒绝缺少一个小时的称重记录。验收入口为 `scripts/verify_native_components.py`，由本项目独立 Worker 环境执行；方案目录明确附带的是合成工程记录。
